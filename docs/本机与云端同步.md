# 本机与云端同步

云端会话（claude.ai/code）跑在一个临时容器里，只能拿到 GitHub 上的东西，碰不到本机 `E:\BassStation`。本机的 Claude Code（桌面版或终端里的 `claude`）直接改本机文件。两边唯一的交接通道是 **GitHub 上的分支**。

## 原则

1. **先备份，再合并。** 任何合并前，本机未提交的改动先提交并推到 GitHub 上一个自己的分支。推上去了就丢不了。
2. **只合并，不覆盖。** 用 `git merge`，不用 `git reset --hard`、`git push --force`、`git checkout -- .` 去“对齐”。
3. **交接前推送。** 本机停手、准备让云端接着做之前，先推送；云端做完也会推到 `claude/...` 或 `design-lab` 这样的分支。
4. **同一批文件不要两边同时改。** 两边同时改 `ReportView.cs` 这类大文件，合并时冲突最多。开工前在 HANDOVER 末尾写一句“正在改哪些文件”。
5. **`main` 保持最新。** 新的云端会话默认从 `main` 开始。`main` 落后时，云端会话会从旧代码起步（2026-10-02 那次就是从初始提交起步的）。阶段性成果合进 `main`。

## 现在要做的一次性对齐（2026-10-02 的状态）

GitHub 上四个分支是一条直线：`main`（初始提交）→ `claude/nifty-hamilton-smvkn0` → `claude/vigilant-keller-9cge3v` → `design-lab`。所以 **`design-lab` 包含云端的全部成果**，本机只需要合并它一个。

在本机 PowerShell 里（`E:\BassStation`）：

```powershell
cd E:\BassStation
git status                      # 看本机有哪些没提交的改动
git log --oneline -5            # 看本机现在在哪个提交上
git remote -v                   # 确认 origin 指向 GitHub 上的 BaSSDream

# 1. 备份本机进行中的工作（ReportView、评测结算页等）
git switch -c local-wip         # 已在某个本机分支上也可以不新建，直接提交
git add -A
git commit -m "本机进行中的改动"
git push -u origin local-wip

# 2. 拿云端成果并合并
git fetch origin
git merge origin/design-lab
#   有冲突：打开冲突文件，保留两边都要的内容，然后
#   git add <文件>; git commit
#   拿不准就停下，让本机的 Claude Code 看冲突再决定

# 3. 编译、跑一遍，没问题再推
dotnet build src-native
git push
```

`tabs/`、`cache/`、`data.db`、模型、`bassdream.json` 都在 `.gitignore` 里，git 不会碰它们，合并不会影响曲库和本机数据。

合并后在 GitHub 上把 `local-wip` 合进 `main`，之后新开的云端会话就从这里开始。

## 以后的日常

- **本机做 → 交给云端**：提交、推送当前分支；告诉云端会话“从 `<分支名>` 继续”。
- **云端做 → 回到本机**：`git fetch origin`，再 `git merge origin/<云端分支>`，编译验证。
- **两边都在做**：各自在自己的分支上，定期互相合并；先合并、后继续写，冲突越早处理越小。
- **只有本机能做的事**：WPF 截图验证（`BassStation.exe --render-*`）、GPU 训练、Guitar Pro 交互。云端做到这里会写“未在真机验证”，回本机时补上。
