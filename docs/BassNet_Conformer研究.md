# BassNet 下一代架构（Conformer 为主线）：理论研究与实验设计

2026-10-20。只做理论分析与方案设计，未做任何训练或评测（本机正在跑其他实验）。文中凡是"预计 / 估计"的数字都没有实测过；凡是项目内的数字都出自 `docs/HANDOVER.md` 中已有的实验结果。

---

## 0. 结论先行

1. **单纯把 BiGRU 换成 Conformer，大概率不会提升音符指标。** 项目内已有很强的证据表明瓶颈在数据和标签，而不在模型容量：v3–v8 改损失、加技法头、加效果器增广、加 MERT、八度宽容训练，验证集都收敛在同一水平；全曲上下文 Transformer 也出现了过拟合（§17.7）。训练数据约 285 首 ≈ 19 小时，处在语音领域里 Conformer 必须靠强正则才能训好的量级。
2. **Conformer 值得做，原因不是"更大的模型"，而是三件 GRU 做不到或很难做的事：**
   - (a) 能以低帧率对**整首歌**做注意力：重复段落、整段八度、半小节相位都是全曲尺度的问题，GRU 的 10 秒切片看不到；
   - (b) 位置编码可以换成**按拍计的旋转位置编码（节拍 RoPE，本文提出）**：注意力直接比较"同一拍位"，并且天然能外推到整首歌的长度；
   - (c) 它是**大规模自监督预训练**的标准骨干（BEST-RQ / MusicFM 就是 Conformer）。预训练是绕开"有标签数据只有 285 首"的唯一途径：无标签的分离贝斯轨可以要多少有多少。
3. **推荐路线**：先做 Conformer-S（与现模型参数量相当，约 5M），验证"不退步，且同音重复起音有提升"；再加节拍 RoPE；最后在**域内贝斯轨上做自监督预训练（BassFM）**，在此基础上微调 Conformer-M。三步各有独立的通过门槛，任何一步不过就停下，不会白白占用 GPU。
4. **架构不限于 Conformer**（§4.0）：主线用 Conformer，第一轮同时跑 **E-Branchformer** 作对照（小数据上更稳）；音高轴注意力（Beat This / hFT 式）作为可选的前端插件；Zipformer 只借鉴它的多帧率结构；Mamba、纯解码器 token 模型不采用。
5. **显存**（§4.7，估算）：Conformer-M、30 秒切片、FP32 全精度，batch 4 约需 5 GB，**3060 Ti 8 GB 上全精度就能训**；5080 16 GB 上可以开到 batch 10–12。唯一会撑爆显存的是音高轴注意力插件，8 GB 上需要给它开梯度检查点。
4. **评测必须先升级**，否则测不出差异：现有标签里约 3/4 的音高分歧其实是模型对（§17.4），更好的模型有可能在旧标签上反而得分更低。架构对比要用逐曲配对的 bootstrap、3 个种子，再加上标签与录音完全一致的独立测试（IDMT 真实 DI、合成渲染、MUSDB 干净贝斯）。

## 1. 现状诊断：问题出在哪个尺度

| 误差类型 | 规模（出处） | 所在时间尺度 | GRU 能否看到 | Conformer 的机会 |
|---|---|---|---|---|
| 同音重复漏起音 | 召回约 74%（§6.3）；漏掉的 2224 个音里约 1700 个模型其实听到了音高（§23） | 10–50 ms | 能看到，但输入分辨率不够（hop 11.6 ms，低音区 CQT 时间模糊） | 卷积模块能直接建模局部瞬态；**但根本问题在前端分辨率**，见 §4.5 |
| 整段八度偏移 | 出错时后验很确定，相邻音也大多在错误的八度（§11.9） | 数秒到整段 | 只能看到 10 秒切片 | 全曲注意力 + 频率轴相对位置；**更可能要靠预训练学到音色不变性** |
| 半小节相位翻转（Henceforth） | 局部证据确实有歧义，整首的结构才能消歧（§22） | 整首 | 看不到 | 节拍 RoPE + 全曲注意力 |
| 模型自信地出错 | 错选音高的中位概率 0.75（§17.7） | — | — | 架构解决不了；预训练能改善校准 |
| 标签与录音不一致 | 约 74% 的音高分歧是模型对（§17.4） | — | — | 与架构无关：**只是测量上限** |

**含义**：Conformer 能触及的是第 2、3 行（全曲尺度），以及第 1 行的一部分。第 4、5 行要靠预训练和评测来解决。这也解释了为什么"全曲上下文 Transformer 只拿离散音符做输入"失败了（§17.7）：它看不到声学证据，只能学音符统计，而音符统计已经被声学模型隐式学到了。Conformer 的全曲注意力作用在**声学特征**上，这是本质区别。

## 2. 最新研究依据（截至 2026-10）

### 2.1 Conformer 及其后续变体
- **Conformer 依然是 2025 年最强的音乐基础模型骨干。** 2025 AMT 挑战赛的冠军系统用 MusicFM 做编码器，MusicFM 就是用 BEST-RQ 掩码预测训练的 12 层 Conformer。MusicFM 的消融里 25 Hz 的版本最好：拍 F1 0.868、强拍 0.804、和弦 0.714，50 Hz 的版本只差一点。→ 对节拍/结构类任务，低帧率注意力就够用。
- **Zipformer**（ICLR 2024）：类 U-Net 编码器，中间几层用更低的帧率，复用注意力权重，用 BiasNorm、SwooshR/L 激活。比之前的模型快 50% 以上，显存更少，收敛更快。→ 本文"全帧率–低帧率–全帧率"的结构就借鉴它。
- **E-Branchformer**：在 20 个基准上与 Conformer 持平或更好，**在大模型或小数据集上训练更稳**。→ 如果 Conformer-S 训练不稳定，这是首选的替换。
- **FastConformer**（NVIDIA Parakeet）：8 倍下采样加深度可分离卷积，乘加运算少 2.9 倍、推理快 2.8 倍；用滑动窗口注意力（局部注意力）加一个全局 token 处理长音频。→ 本项目需要整首歌的推理（约 4 分钟），可以直接用"局部注意力 + 全局 token"这套做法。
- **位置编码**：ASRU 2025（Samsung，SpeechBrain）在 100–50,000 小时的数据上对比了 RoPE 与相对位置编码：错误率持平或更好，训练时间最多少 21%，而且 RoPE 与高效注意力实现兼容。→ 用 RoPE，不用 Transformer-XL 式的相对位置编码。
- **小数据正则**：中间层 CTC（InterCTC）加随机深度在 81–207 小时的数据上都有效，在 100 小时的设定下主要起正则作用（Uconv-Conformer），在 LibriSpeech 100 h 上相对改善 13–14%。→ 本项目没有 CTC，但"在中间层加辅助帧音高损失"是同一个原理（§4.6）。

### 2.2 音乐转录 / 节拍方面
- **Beat This!**（ISMIR 2024）：卷积与 Transformer 交替，Transformer 在频率轴和时间轴之间交替做；损失函数容忍标注的小幅时间偏移；不用 DBN 后处理。（它是否用 RoPE，摘要里没写；其移植版依赖 `rotary-embedding-torch`，只能推测。）本项目实测它不如我们自己的节拍头（§11.9），**但它的"频率轴/时间轴交替注意力"结构仍可借鉴**。
- **hFT-Transformer**（ISMIR 2023）：频率轴和时间轴分层注意力，在 MAESTRO 上达到当时最佳。→ 频率轴注意力可以学"候选八度之间的比较"。
- **音频到乐谱、按拍对齐**：ICASSP 2026（Shanin 等，QMUL）在爵士独奏上用交叉注意力把帧级声学特征与按拍对齐的节奏嵌入对齐，取得最佳结果；同时指出端到端自回归解码器需要大量数据，也不保证写出合法的乐谱。→ 支持"声学编码器 + 拍网格解码"的路线，不支持直接用 token 解码器。
- **RotIE**（2026，符号音乐）：把 RoPE 推广到编码任意整数属性（音高、绝对时间、小节内位置），困惑度低于普通 RoPE 和 Music Transformer，**长序列上尤其明显**。→ 节拍 RoPE 的直接前例，但 RotIE 针对的是符号序列，**还没有人把它用在由估计拍点驱动的音频帧上**。
- **MuScriptor**（2026-07）：纯解码器 Transformer，5 秒 16 kHz 梅尔谱作前缀，输出 MT3 式音符 token；60M–1.3B 参数；合成预训练 → 17 万首真实录音微调 → 强化学习。→ 它的数据量是本项目的上千倍，所以**不要模仿它的规模**；可以借鉴的是"最后用强化学习优化不可微的指标"（§6.3）。
- **Mamba**：语音上与 Conformer 互有胜负，在高分辨率任务上优势更大；钢琴转录上有 2025 年的学位论文报告推理快约 45 倍、精度相当。→ 目前没有在音乐转录上与 Conformer 做过对照的结果；本项目的瓶颈不在速度，**暂不考虑**。
- **PESTO**（ISMIR 2023 / TISMIR 2025）：用移调等变的自监督目标训练音高估计，13 万参数、无需标签，与有监督方法相当。→ CQT 上的"移调一致性"可以直接用作无标签数据的损失（§5.2）。

### 2.3 项目内必须尊重的反例
- MERT-330M 冻结特征（PCA 384）没有提升（§11.11）。→ **"通用预训练"不等于"域内预训练"**：MERT 是在混音上以 75 Hz 训练的，目标是通用音乐表示，从未专门学过贝斯。BassFM 方案（§5）把预训练放在分离后的贝斯轨上，并且端到端微调而不是冻结 PCA 特征。尽管如此，这个反例确实降低了对预训练收益的先验预期。
- 全曲上下文 Transformer（离散音符输入）过拟合（§17.7）；重复一致性（−3%）、规整的收益都很小（§6.3、§18.5）。→ 全曲注意力的收益**不能**靠"硬性让重复段一致"来获得，只能让模型在声学证据上自己学习权衡（§4.4 用可学习、初始为 0 的偏置）。

## 3. 数据量与模型规模的匹配

| | 数值 | 说明 |
|---|---|---|
| 有标签数据 | 约 285 首 × 约 4 分钟 ≈ 19 小时 ≈ 590 万帧（86 fps），训练音符约 17.3 万 | §17.2、§17.7 |
| 外部教师标签 | MUSDB 150 + MoisesDB 236 ≈ 386 首，约 25 小时 | §22 老师—学生，已在进行 |
| 现模型参数 | 约 3.4M（估算：GRU 两层双向约 2.45M，pitch_proj 约 0.59M，其余约 0.3M） | 由 `model.py` 推算 |
| Conformer-S | d=192，2+4+2 块，约 5M | 无预训练时的上限 |
| Conformer-M | d=256，2+6+2 块，约 13M | **只在预训练之后**使用 |

语音领域的经验是：在 100 小时以下，Conformer 只有配合 SpecAugment、随机深度、中间层损失等强正则，才能稳定地胜过 BLSTM（Switchboard 上同参数量胜过 BLSTM 约 9% 相对，但那里有 300 小时）。本项目 19 小时的规模更小，所以 S 版要严格对齐现模型的参数量，避免把"容量变化"和"结构变化"混在一起。

## 4. BassConformer 架构设计

### 4.0 候选架构比较（约束：16 GB 跑 FP32 全精度，8 GB 可用）

| 架构 | 证据 | 对本项目的利弊 | 结论 |
|---|---|---|---|
| BiGRU（现行） | v3–v8 | 稳定；看不到全曲；不能并行，长切片训练慢 | 基线 |
| **Conformer**（U 形多帧率 + RoPE） | MusicFM / 2025 AMT 冠军的骨干；ASR 的主流 | 局部卷积适合起音，注意力能看全曲；有成熟的预训练配方 | **主线** |
| **E-Branchformer** | 20 个基准上持平或更好，大模型、小数据上训练更稳 | 结构与 Conformer 同级，显存相近（并行的注意力分支 + cgMLP 分支） | **E1 的对照组**，两条一起跑 |
| Zipformer | 比 Conformer 快 50% 以上、显存更少 | 收益部分依赖它专用的 ScaledAdam 优化器和 BiasNorm/Swoosh，脱离 icefall 移植的工作量大 | 只借鉴多帧率 U 形结构（已用于 §4.1） |
| 频率–时间交替注意力（Beat This、hFT-Transformer） | 节拍与钢琴转录上效果好 | 沿音高轴的注意力可以直接比较"同一时刻的各个候选八度"，针对八度错误；**显存代价最大**（每帧 48 个音高 token） | 作为前端的可选插件（E1c），1 块，d=32 |
| 纯 Transformer（无卷积） | — | 低资源下一般不如 Conformer；局部瞬态只能靠注意力学 | 不单独做 |
| Mamba / 混合 | 语音上与 Conformer 互有胜负；钢琴上快约 45 倍 | 优势在速度和超长序列，本项目不缺这两样；`mamba-ssm` 的 CUDA 内核对 Windows 支持差，纯 PyTorch 版很慢；音乐转录上没有和 Conformer 的对照 | 不采用 |
| 纯解码器 token 模型（MuScriptor、MT3） | 需要数十万首的数据 | 数据差三个数量级；YourMT3+ 实测远不如 BassNet | 不采用 |

### 4.1 总体结构

```
CQT(264) ─► 谐波堆叠 + 现有 4 层卷积（保留，沿音高方向等变）─► 每音高特征 (48×48)
                                                                   │
混音 mel ─► 现有 mel 分支 ┐                                         ▼
分离轨宽频分支 ───────────┼──► 拼接 → 线性投影到 d ─► [A] 全帧率 2 块（86 fps，局部注意力 ±64 帧，卷积核 15）
                          ┘                                         │ 步长 4 下采样
                                                                    ▼
                                                     [B] 低帧率 4–6 块（21.5 fps，全曲注意力 + 节拍 RoPE + 自相似偏置，卷积核 15）
                                                                    │ 上采样 + 与 [A] 的跳连相加（Zipformer 式）
                                                                    ▼
                                                     [C] 全帧率 2 块（局部注意力）
                                                                    │
                       ┌────────────────────────────────────────────┤
                       ▼                                            ▼
            帧音高头（保留 per-pitch 局部旁路）          起音 / 闷音 / 拍 / 强拍 / 技法头（输出与现模型完全一致）
```

**要点**
- **输出接口不变**：`(frame, onset, dead, beat, down[, tech])`，所以 `decode.py`、`pipeline.py`、`eval_cached`、`song_eval`、`models.json` 的按角色集成、移调 TTA 全部不用改。`load_checkpoint` 按检查点里的 `arch` 字段构建（加一个 `"backbone": "conformer"` 即可），新旧模型可以混合集成。
- **前端卷积全部保留**：谐波堆叠 + 沿频率方向的膨胀卷积（3 / 12 格）沿音高方向近似等变，这是移调增广和 TTA 有效的基础。Conformer 只替换时间方向的建模（GRU）。
- **起音头只接全帧率分支**：起音需要 11.6 ms 的分辨率，绝不能从低帧率分支上采样得到（FastConformer 那种 8 倍下采样会直接毁掉起音）。

### 4.2 Conformer 块的配置（采用 2024–2026 的稳妥做法）
- Macaron 结构：½FFN → MHSA → 卷积模块 → ½FFN → 归一化；前置归一化（RMSNorm 或 LayerNorm 均可）；FFN 用 SwiGLU，扩展比 ×2.67（参数量与 ×4 的 GELU FFN 相当）。
- 注意力：4 个头；**RoPE**（据 ASRU 2025 的结果，与相对位置编码持平或更好，且能用 PyTorch 的 `scaled_dot_product_attention` 高效实现，适合 8 GB 显卡）。
- 卷积模块：逐点卷积 → GLU → 深度卷积（核 15）→ BatchNorm → SiLU → 逐点卷积。核 15 在 86 fps 下约 175 ms，在 21.5 fps 下约 700 ms（约为 BPM 170 时的两拍）。
- 正则：随机深度 0.1（从浅层到深层线性增加）；注意力和 FFN 的 dropout 0.1；训练时保留现有全部增广（±3 半音、±10% 时间伸缩、增益、频谱倾斜、噪声）。
- **训练 / 推理一致性**：§21 已踩过的坑是"冻结层的 dropout 在训练时开着"。Conformer 里 BatchNorm 位于卷积模块中，小批量、长切片时统计量不稳 → 卷积模块里改用 LayerNorm 或 GroupNorm 更安全（这是工程判断，不是文献结论）。

### 4.3 创新点一：节拍 RoPE（Metrical RoPE）

**动机**：在拍子和小节层面，音乐的位置是周期性的，帧序号只是它的一个糟糕的代理。Henceforth 的错误是局部"第 1 拍和第 3 拍听起来一样"，消歧要靠整首歌里同一乐句的拍位关系。

**定义**：令 φ(t) 为帧 t 处的连续拍数（拍序号 + 拍内相位，由拍点插值得到），ψ(t) 为连续小节数。把每个注意力头的 d_h 维分成三组：
- **时间组**（d_h/2）：普通 RoPE，角度 = t·ω_i，表示绝对的远近；
- **拍组**（d_h/4）：角度 = 2π·k·φ(t)，k ∈ {1, 2, 3, 4, 6, 12}（拍、八分、三连音、十六分、十六分三连音、48 分）；
- **小节组**（d_h/4）：角度 = 2π·k·ψ(t)，k ∈ {1, 2}（小节、半小节）。

由 RoPE 的性质，q(t)·k(s) 只依赖 φ(t)−φ(s) 和 ψ(t)−ψ(s) 各自在 k 次谐波上的余弦。于是注意力天然地"不随速度变化"，只看相对拍位：120 BPM 和 180 BPM 下的同一乐句在拍组里完全一样。

**为什么能外推**：拍组和小节组是**周期函数**，训练时用 30–60 秒的切片，推理时用整首（4 分钟），不存在普通 RoPE 的长度外推问题（RotIE 在符号音乐上也观察到长序列上的优势）。

**鸡和蛋的问题（拍点要从哪来）及解法**：
1. **两遍推理**：第一遍关掉拍组和小节组（置零），得到拍/强拍后验 → 现有 `pipeline.song_beats`（HMM + 重复权重）→ φ, ψ → 第二遍完整推理。CPU 上的额外开销是秒级，GPU 上是多跑一遍前向（每首约几秒）。
2. **训练**：φ/ψ 用 labels_v2 的真实拍点，加 ±20 ms 抖动；20% 的样本整组置零（与第一遍的情形一致）；15% 的样本改用第一遍模型的预测拍点（模拟推理时的误差，避免训练和推理不匹配）。
3. **小节组的风险**：若第一遍的强拍相位本身是错的（正是 Henceforth 的情况），小节组就会把错误"锁死"。所以小节组的训练里要有 10% 的样本**故意把 ψ 平移 1 或 2 拍**，同时强拍的监督保持真值，迫使模型在"小节组提示"与"声学证据"冲突时学会相信声学。这是该设计里最需要实测确认的地方。

**可证伪的预期**：主要改善小节线 / 强拍相位（`bar_exact`、首小节、强拍 F1）和三连音细分；对音高几乎没有影响。若只有拍组有效、加小节组反而变差，说明锁死效应占了上风，就只保留拍组。

### 4.4 创新点二：自相似偏置注意力（只在低帧率分支）

attention_logit(t, s) += λ_h · S(b(t), b(s))

- S：按拍同步的贝斯轨 CQT 音名分布（或第一遍的帧音高后验）的余弦相似度矩阵，z 分数归一化；b(t) 是帧 t 所在的拍。
- λ_h：每个头一个可学习的标量，**初始化为 0**（初始时就是普通注意力，模型可以学会忽略它）。
- 与之前失败做法的区别：重复一致性（−3%）、规整都是**硬**改写音符；这里只是给注意力"提示哪里可能是同一乐句"，最终证据仍是各自的声学特征。整段八度错误正是需要这种机制的地方：同一乐句的另一次出现可能更清楚（例如吉他没那么响）。
- 计算：每首约 600–700 拍，S 是 700×700 的矩阵，开销可以忽略。

**预期 / 风险**：整段八度和同乐句的写法一致性可能改善；风险是"把错误也传染给所有重复"。必须看逐首的分布，不能只看均值。

### 4.5 起音分辨率：Conformer 解决不了，需要一起改前端
同音重复漏起音的根源是输入：hop 256（11.6 ms），以及低音区 CQT 窗口长达约 1 秒（§12）。Conformer 的卷积模块对此帮助有限。建议与 Conformer 同时引入：
- **高时间分辨率的起音前端**：分离轨的短窗 STFT（hop 64，约 2.9 ms）或原始波形的步长卷积，池化到 86 fps 后作为第 4 路输入，只送进 [A]/[C] 全帧率分支。
- **起音偏移回归**：起音头输出"是否起音"之外，再回归帧内的偏移（Kong 等人 2021 年高分辨率钢琴转录的做法），解码时得到亚帧级的起音时间。
- **复数域 / 相位偏差起音特征**（Bello、Dixon 2006）：同音重新拨弦时，谐波的相位会被重置，即使能量没有下降。可以作为一路便宜的手工特征拼到输入里。Essentia 的文档提醒它在打击性声音上容易多检，在贝斯分离轨上需要实测。

### 4.6 训练目标的小改动
- **中间层辅助损失**：在 [B] 的输出上加一个轻量的帧音高头（相当于 InterCTC），权重 0.3。在低资源设定下，这是被反复证实的正则手段。
- 其余损失不变（帧音高 CE、起音 / 闷音 BCE、拍 / 强拍、技法），继续支持 `--rep-w/--sus-w/--oct-tol`，便于和 v4/v7o 的配方一一对照。
- 切片长度：10 秒 → **30 秒**（[B] 要能看到至少 2–3 个乐句）；为了保证每个 epoch 看到的帧数相同，把批大小相应缩小。整首歌的注意力在推理时使用（拍组、小节组可以外推；时间组 RoPE 的基频取足够大，或者对 [B] 使用局部 ±512 帧加全局 token，与 FastConformer 的做法相同）。

### 4.7 显存预算（FP32，估算，未实测）

现行训练：`--bs 12`、10 秒切片（每批约 1.03 万帧）、fp16 autocast，跑在 8 GB 上。下面按"每帧要保存多少个浮点数供反向传播"来估算：

| 部分 | 每帧保存的激活（浮点数） | 估算方法 |
|---|---|---|
| 前端（谐波堆叠 + 4 层卷积，32/32/48/48 通道 × 144 个音高格） | 约 5 万 | 每层保存卷积输出与 BN 输出：2 × (32+32+48+48) × 144 ≈ 4.6 万，加上谐波堆叠 |
| Conformer 全帧率 4 块（[A]+[C]，d=256，局部窗 129） | 约 3.5 万 | 每块约 30d ≈ 7.7 千（两个半 FFN 各约 7d，注意力约 6d，卷积模块约 6d，残差与归一化约 4d），加注意力分数约 1 千 |
| Conformer 低帧率 6 块（[B]，帧数 ÷4） | 约 1.2 万 | 6 × 7.7 千 ÷ 4；645 个 token 的全注意力分数可以忽略 |
| 合计 | 约 10 万 ≈ **每帧 0.4 MB（FP32）** | |

| 设置 | 每批帧数 | 激活 | 参数 + 梯度 + AdamW（13M 参数） | 总计（另加约 1.5 GB 的 CUDA 上下文和碎片） |
|---|---|---|---|---|
| 30 秒 × batch 4（每批帧数与现行相同） | 1.03 万 | 约 4.1 GB | 约 0.2 GB | **约 5.8 GB：8 GB 上 FP32 可训** |
| 30 秒 × batch 8 | 2.06 万 | 约 8.3 GB | 约 0.2 GB | 约 10 GB：16 GB 上 FP32 |
| 30 秒 × batch 12 | 3.1 万 | 约 12.4 GB | 约 0.2 GB | 约 14 GB：16 GB 的上限 |
| + 音高轴注意力插件（1 块，d=32，48 个 token） | — | 每帧再加约 5 万 | — | 激活约翻倍；8 GB 上需要对插件和前端开梯度检查点（慢约 30%），或改用 fp16 |

- **推理**：整首 4 分钟约 2 万帧，不保存激活，FP32 下 8 GB 绰绰有余；全曲注意力只在 [B] 分支（约 5 千个 token），注意力矩阵约 0.4 GB。
- **全精度的含义**：若要求严格 FP32，需要设 `torch.backends.cuda.matmul.allow_tf32 = False`（Ampere 及以后的显卡默认可能用 TF32 做矩阵乘法）。现行 `train.py` 用的是 fp16 autocast；Conformer 的注意力在 fp16 下更容易溢出，FP32 本身就是更稳的选择。
- 这些数字的误差可能有 ±50%（PyTorch 的分配器碎片、cuDNN 的工作区）。正式开训前，先用 `torch.cuda.max_memory_allocated()` 跑 20 步实测。

## 5. 创新点三：域内自监督预训练 BassFM

### 5.1 数据
- 无标签的分离贝斯轨：曲库 297 首 + MUSDB/MoisesDB 386 首（已有）+ 用户自有的其他音乐（任意数量，只需要用 BS-Roformer-SW 分离，每首 25–40 秒 GPU）。1000 首约 67 小时，是现有标签数据的 3.5 倍；3000 首约 200 小时。
- 这部分数据不需要谱，不进入验证/测试集（按 `split_keys.json` 的歌曲键排除），不违反任何现有规则。

### 5.2 目标（三项联合）
1. **BEST-RQ 掩码预测**（MusicFM 的做法）：对归一化后的 CQT 帧做随机投影，再查随机码本得到离散 id；以约 400 ms 的跨度掩掉 30–40% 的帧，预测被掩部分的 id。不需要训练分词器，实现简单，对帧级任务效果好（HingeNet 的结论）。
2. **移调等变一致性**（PESTO 的思路）：同一切片沿 CQT 平移 k 格（k ∈ ±12 半音，×3 格/半音），要求帧音高头的输出也平移 k 个类别（对称 KL）。它直接针对"整段八度错误"：强制模型在不同音区上用同一套判断，而现在的模型可能学到了"某种音色就在某个八度"的捷径。
3. **（可选）教师伪标签**：v3+v4 在无标签贝斯轨上的高置信度帧（后验 > 0.9）作为软目标，权重低。规则（09-30）允许这样做，前提是评测用独立标签。

### 5.3 微调
- 先冻结骨干，只训输出头 2 个 epoch；然后全部解冻，逐层学习率衰减 0.8。
- 对照组：同一架构、随机初始化、同样的步数。**只有这个对照才能说明预训练有没有用。**

### 5.4 成本估计（RTX 3060 Ti 8 GB，180 W 限功率，未实测）
- 分离 1000 首：约 8–11 小时 GPU（每首 25–40 秒）。
- 预训练 Conformer-M（约 13M 参数，30 秒切片，FP32）：粗略估计 3060 Ti 上 1–2 天，5080 上更短。可以按 `thermal.guard()` 分段在空闲时跑。
- 微调：与现有训练相当（每 epoch 约 2–3 分钟，40 epoch）。

### 5.5 对 MERT 反例的回应与诚实的先验
MERT 没有提升，可能的原因：(1) 在混音上训练，贝斯信息只占很小一部分；(2) 冻结特征再做 PCA，丢掉了细节；(3) 75 Hz、24 kHz 的设定对低音区不友好；(4) 训练时移调样本必须把 MERT 置零（§11.11），最强的增广用不上。BassFM 在这四点上都不同（贝斯轨、端到端微调、CQT 输入、可以随 CQT 一起移调）。尽管如此，**预计收益仍按"0 到 +2 个音符 F1 点"来估计**，并且只有在独立测试集上看到才算数。

## 6. 与"大模型"技术的关系（哪些借鉴，哪些不借鉴）

| 技术 | 结论 | 理由 |
|---|---|---|
| RoPE、SwiGLU、前置 RMSNorm、`scaled_dot_product_attention` | **采用** | 零成本，有 ASR 上的对照证据 |
| 自监督预训练 → 微调 | **采用（BassFM）** | 绕开标签稀缺的唯一手段 |
| 纯解码器 token 模型（MuScriptor / MT3 路线） | 不采用 | 数据量差三个数量级；YourMT3+ 实测远不如 BassNet（§11.11）；不保证写出合法的谱 |
| MoE | 不采用 | 19 小时的数据撑不起多个专家 |
| 测试时计算（多次推理投票） | 已有（移调 TTA + 集成） | 可以把 TTA 扩展到时间伸缩 ±5% |
| 强化学习优化不可微指标 | **以后再考虑** | MuScriptor 用 RL 做最后一步。可以把"量化后小节完全一致""重合成相似度"作为奖励，只微调解码层或起音阈值头；必须等独立金标准集建好以后，否则会对旧标签的噪声过拟合 |
| 长上下文（滑动窗口 + 全局 token） | **采用（[B] 分支推理）** | FastConformer 已证实可行 |

## 7. 实验设计（以后在本机执行；每一步都有通过门槛）

### 7.1 评测先行：测量误差有多大
- **噪声带**：用 v4 配方 + labels_v2（即 v8）跑 3 个种子，得到验证集各指标的种子间标准差。以后"有提升"的标准 = 差值 > 2 倍标准差，**并且**逐曲配对 bootstrap（按歌曲重采样 10,000 次）的 95% 置信区间不跨 0。
- **独立的仲裁集**（标签与录音一致，不受谱面写法影响）：
  1. IDMT-SMT-Bass-Single-Track（17 条真实 DI，现在音符 F1 0.845、音高 96.8%，§20）；
  2. `sep_stress` 的合成渲染（8 种音色 × 正常电平 / −9 dB，标签完全正确）；
  3. MUSDB test 50 首：分离轨上扒出的结果 vs 干净贝斯上扒出的结果（§21，现在 F1 0.8275）。
- **分项指标**：同音重复的起音召回、休止后首音召回、八度错误率、"自信地出错"的比例（错误中概率 > 0.8 的占比）与 ECE、小节线 / 首小节 / 强拍 F1、记谱音符准确率。Conformer 的预期收益集中在分项上，总 F1 很可能看不出来。

### 7.2 消融阶梯

| 步骤 | 内容 | 通过门槛（验证集；测试集只在最后报告） |
|---|---|---|
| E0 | v8 配方 3 个种子 | 得到噪声带 |
| E1 | Conformer-S 与 E-Branchformer-S 两条并行（无节拍 RoPE、无自相似偏置）、30 秒切片、各 3 个种子 | 总音符 F1 不低于 E0 超过 1 个点，**且**同音重复召回 +2 个点以上，或独立仲裁集上更好；两条都不过就停 |
| E1c | 胜出者 + 音高轴注意力插件 | 八度错误率下降，音符不退步 |
| E1b | E1 + 高分辨率起音前端 + 偏移回归（§4.5） | 同音重复召回、起音时间误差的中位数 |
| E2 | + 节拍 RoPE（先只用拍组，再加小节组） | 小节线 / 首小节 / 强拍 F1 提升，音符不退步 |
| E3 | + 自相似偏置 | 八度错误率下降，且逐首变差的歌不多于变好的 |
| E4 | BassFM 预训练 → Conformer-M 微调，与随机初始化的 Conformer-M 对照 | 独立仲裁集与验证集同时提升 |
| E5 | + 外部老师—学生数据（§22 已在准备） | 同上 |
| 上线 | 与 v3+v4 按角色集成（`models.json`）；五维评测；快照 | 按惯例：验证集选，测试集确认，GP8 实机截图 |

### 7.3 预期结果（写在这里，以便事后核对）
- H1：E1 的总音符 F1 与 E0 的差在 ±1 点以内（数据瓶颈）。
- H2：E1/E1b 的收益主要出现在同音重复召回上。
- H3：E2 改善结构类指标，对音高没有影响。
- H4：八度错误只有 E4（预训练 + 等变一致性）才能明显降低；E3 的影响不确定。
- 若 H1 不成立（E1 明显更好），说明 GRU 本身就是瓶颈，之前的判断要修正。若 E4 也没有提升，就说明"数据瓶颈"指的是**有标签数据的质量**而不是数量，下一步应全力建设金标准集和核对版回流，而不是继续调架构。
