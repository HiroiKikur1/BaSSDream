## 0. 结论先行

1. **真实误差最大的一项是音符切分（起音）**：IDMT 真实 DI 上音符 F1 0.845，而匹配上的音音高对了 96.8%（§20）。**第二是分离**：MUSDB 真实多轨上，分离轨和干净贝斯轨扒出的音符一致率只有 F1 0.8275（§21）。**"没输出"的缺口**是技法（约 8–10% 的音）和指法（与真实演奏者同弦 72%）。对照参考谱的音高"错误"约 3/4 是谱错，真实音高误差估计只有 2–4%。
2. **金标准改用"官方总谱 + 用眼睛核对"，不需要耳朵**：4 本官方总谱约 41 首，把贝斯声部数字化后，与雪鹽子谱、与模型三方比对。两份独立人工谱一致的地方就是可信的真值；不一致的地方标"存疑"，单独统计。曲库里没有的歌（结束バンド 全部、Afterglow 大部分）直接成为**从未训练过的独立测试集**（§1）。
3. **现有模型一个都不扔，包括 v10 和 conf1（v11）**：它们是用真实录音 + 购买谱训练的，不是合成数据。当前最好的那个（v11）就是第一代教师：给 1 万首无标签音乐打伪标签、当回归基线、当集成成员；现有的标签（labels_v2）、解码 / 量化 / 写谱链路也全部继续使用（§3.1）。
4. **没有 DadaGP 也能做大规模合成数据**：用 338 份购买谱（有技法和指法）做符号增广，再加 Lakh MIDI（17.6 万个文件）里的贝斯轨提供多样性；贝斯音源以物理建模的 MODO BASS 2 为主（可以连续改琴型、弦、拨弦位置和方式），加 2–3 个采样音源；箱模用免费的 TONE3000（2026-09 发布，70 万+ NAM 捕获，含贝斯）（§3.3）。
5. **选弦能不能从录音里听出来，你的怀疑有道理**：文献里孤立单音的选弦识别 F 值约 0.93（4 弦贝斯），但那是干净单音；在分离、压缩、过载之后会弱很多。先用你自己的琴做一个 1 小时的小实验量出来（§4.5），再定规则：录音能分辨时以录音为准，分辨不了时按好弹的习惯。
6. **"力大砖飞"是可行的，前提是数据先扩大**：部署约束很宽，1B 参数 FP32 的权重只有 4 GB，16 GB 卡能跑，8 GB 卡分块也能跑；每首 1 小时的预算允许大集成、TTA、"生成 + 验证"式的搜索。路线：先在本机用 M 版做规模律实验，确认"数据加倍 → 误差下降"，再租卡放大到 100M（L 版）；按压缩后的预算（§6.2），1B 不做（§5.1、§5.2）。
7. **分离与扒谱可以深度融合，而且这是最有希望的架构方向**：分三步：取分离模型的中间特征 → 分离与扒谱联合微调 → 共享骨干的一体模型（同时输出 6 轨、贝斯音符、拍点、技法、弦证据），扒谱分支直接"看到"鼓和吉他，串音问题由模型内部处理，不再需要单独的降噪（§5.3）。
8. **"一次算不对就多算几次"可以先免费测**：同一个分离模型重复跑结果完全一样，必须换着方式跑（错开分块、反相、左右互换、开 dropout、换模型）才有差别；分离的错误大多是系统性的，多跑只能消掉不相关的那部分。先用 `sep_multi.py` 量出"至少一遍对"的上限和各遍错误的重合度，再决定要不要放进正式流程。相位估计改善的是波形，BassNet 读的是 CQT 幅度，所以这一步收益有限（§9.1）。直接输入波形：不替换 CQT，而是加一个看波形 / 相位的起音分支（§9.2）。成绩置信度：测试集按歌曲 bootstrap 给误差条，版本对比用配对 bootstrap；新歌没有答案时，用校准过的逐音置信度 + 多遍一致率估计分数，再用保形预测给区间（§9.3）。

### 1.3 不靠耳朵的核对流程
1. **数字化（用眼睛）**：在软件内谱面（`ScoreView`，§23）里打开模型的扒谱，**对照纸质书逐小节看**，把不同的地方改成书上的写法，改完的区间标"已审核"。这只需要看谱对谱，不需要听。估计每首 30–60 分钟（约 100 小节）。可选加速：手机拍 TAB 页，用多模态模型读出初稿，再人工逐小节对照（先拿一页测准确率，再决定用不用）。
2. **版本核对**：官方总谱对应 CD 版，曲库里可能是 Live 版 / game size 版。录音必须和书的版本一致：用户提供 CD / 正版音源，按"本地音频扒谱"流程导入。
3. **三方比对**：
   - 官方 = 雪鹽子：高可信真值，用于打分；
   - 官方 ≠ 雪鹽子：标"存疑"，用信号裁判（`audio_verify`）给出倾向，单独统计，不计入主分；
   - 只有官方（新歌）：官方为真值，同时记录信号裁判与它的分歧率，作为官方谱自身误差的估计。
4. **双人一致率 = 现实天花板**：重叠歌上，"官方 vs 雪鹽子"的一致率就是人与人之间的上限。模型达到这个水平以后，再往上的"提升"已经无法用人工谱判定。

### 1.4 规则
- 金标准歌**永不进训练**。重叠歌如果当前在训练集里：用于标签清洗和天花板测量，不当测试用；只有在 val/test 里的才直接当金标准。
- 统计：先用当前配方跑 3 个种子测出波动；"有提升"= 差值超过 2 倍标准差，**并且**按歌曲配对的 bootstrap（10,000 次）95% 置信区间不跨 0。约 30 首 × 平均约 400 音，按歌曲 bootstrap 估计能分辨 1–1.5 个点的差异。
- 数字化的总谱只在本机自用，不外传。

### 3.3 合成渲染管线
**目标**：标签 100% 正确，覆盖切分（A）、技法（F）、弦 / 品（G），以及被埋 / 失真（B）。SynthTab 证明：用 DadaGP 渲染的吉他数据预训练，在所有同数据集、跨数据集实验里都更好，对弦 / 品的收益比对音高更明显。

**贝斯音源（需要多少）**：多样性比数量重要。要覆盖的维度：琴型 / 拾音器（P、J、主动双线圈、5 弦）、琴弦（圆绕 / 平绕、新 / 旧）、拨弦方式（指弹、拨片、slap/pop、手掌闷音）、拨弦位置、技法（滑音、击勾弦、闷音、揉弦、泛音）。
| 优先级 | 音源 | 理由 | 获取 |
|---|---|---|---|
| 1 | **IK MODO BASS 2（完整版）** | 物理建模，一套就能连续改琴型、4/5/6 弦、弦规 / 弦龄 / 平绕、演奏方式（指弹 / slap / 拨片 / 闷音）、演奏位置，MIDI 可控制滑音、揉弦、闷音；同一音高可以指定在哪根弦上弹，**正好用来生成弦 / 品标签** | 购买；免费的 CS 版只有一个 60 年代 P Bass 模型，可以先用它跑通管线 |
| 2 | Ample Bass P Lite（免费） | 采样型，与物理建模的声音特性不同，增加多样性；有击勾弦、连音滑、手掌闷音 | 免费；音域只到 D1，覆盖不了 5 弦低 B |
| 3 | 1–2 个商业采样贝斯（如 Ample 的完整版） | 真实采样，补充 slap 等 | 视预算 |
| 4 | **你自己的 4 弦 / 5 弦琴的 DI 录音** | 最真实的音色 | 见 §3.4 |

建议起步：MODO BASS 2 完整版 + Ample P Lite + 你自己的琴。按琴型 × 拨弦方式 × 设置算，约 20–40 种可区分的音色，已经远多于现在训练数据里的音色种类。

**除了 MODO BASS 2 还要不要买别的**：起步阶段不需要。需要的另外两样都是免费的：Ample P Lite（采样型），以及 TONE3000 的箱模和免费箱体 IR。之所以保留至少一个采样型音源和你自己的 DI，是因为只用一种合成引擎时，模型可能学到这个引擎特有的痕迹（例如物理模型的起音形状），换到真实录音上就失效。判断要不要再买一个商业采样贝斯，看 P1 试点的结果：如果"只用合成数据训练"的模型在 IDMT 真实 DI、MUSDB 干净贝斯上的表现，明显不如它在合成测试集上的表现（合成到真实的差距大），就再加一个采样音源；差距小就不用。

**箱模 / 效果器**：TONE3000 免费插件（2026-09-01 发布，开源，VST3/AU/CLAP/LV2，Windows/macOS/Linux；库内 70 万+ 个 NAM A2 捕获，含贝斯箱头）。建议选 30–50 个贝斯捕获，覆盖：干净 DI、电子管、过载、fuzz、SansAmp 类前级；再加 10–20 个箱体 IR，以及随机压缩 / EQ。另外保留 20% 的"纯 DI"样本。

**谁来算（本机 CPU vs 租用 GPU）**：
- 商业 VST（MODO、Ample）只有 Windows/macOS 版 → **只在本机渲染干声 DI**（用 Spotify 的 `pedalboard` 或 DawDreamer 加载 VST3 乐器、喂 MIDI、离线出音频；有的插件会崩，需要子进程隔离）。
- 箱模、IR、压缩、混入伴奏、电平随机化，都放到**租用的 GPU 上训练时实时做**：NAM 本身是神经网络，开源，可以在 PyTorch 里批量推理。需要先确认 A2 格式能否脱离插件推理；不行就选 A1 格式的捕获，或者在本机渲染一部分。
- 这样本机只承担"MIDI → 干声"这一步，CPU 压力最小。上传量：22.05 kHz 单声道 FLAC，每 100 小时约 10 GB。先渲染 1 小时测速度，再定总量（目标 300–1000 小时）。

**混音**：伴奏来自曲库 6 轨分离里的非贝斯部分（240 首，§21）+ MUSDB/MoisesDB 的真实分轨；贝斯电平随机在 −12…+3 dB；再过一遍分离（级联方案），或直接输入一体模型（§5.3）。

**风险**：合成与真实的域差距（§17.5 的教训：加法合成太"干净"）→ 合成数据只用于预训练，最后一定用真实数据微调，并以金标准 / 仲裁集验收。

### 3.4 DI 录音回流（用户同意，前提是没有负面影响）
**数据从哪来**：演奏评测已经保存每次录制（`performance_takes`）和逐音判定（§14、§22）。判为 PERFECT/GREAT 的音 = 你确实按谱弹出的音，弦 / 品已知，时间到毫秒。

**可能的负面影响及对策**：
| 风险 | 对策 |
|---|---|
| 把你弹错的音当成真值 | 只取 PERFECT/GREAT 且音高通过检查的音；其他时段在损失里屏蔽 |
| 评测器是用 BassNet 判定的，可能只选出"模型本来就会的"简单音（自我强化） | 降低权重；统计回流数据里同音重复、休止后首音等难例的占比；有偏就补采样 |
| DI 太干净，与分离轨域不同 | DI 混入别的歌的伴奏 → 过分离 → 再训练，与真实输入同域 |
| 评测泄漏 | 按歌曲排除金标准 / val / test 歌 |
| 总体变差 | **只有在金标准 + 仲裁集上不变差才采用**；每次回流前快照，可以回滚 |

按这套门槛，"没有负面影响"是通过验收来保证的，而不是假设出来的。

### 3.5 无标签音乐 + 自训练（noisy student）
**1 万首够不够**：按平均 4 分钟算约 670 小时，是现有有标签数据（约 19 小时）的 35 倍，足够启动自监督和第一轮自训练。要不要继续下载，由 §5.1 的规模律实验决定：用 25% / 50% / 100% 的无标签数据各训一次，如果 100% 仍明显好于 50%，就继续下载；已经持平就不用再下。
- **相关性比数量重要**：优先保留贝斯清楚的乐队音乐（J-Rock、动画、ボカロ乐队版、融合 / Slap 系）；过滤纯人声、古典、电子乐里没有贝斯或贝斯是合成器长音的曲目（可以用分离后贝斯轨的能量与起音密度自动筛）。
- **去重与隔离**：按音频指纹 / 标题去重；曲库歌、官方总谱的 41 首、val/test 歌一律排除，避免评测的音频进入预训练。
- **在哪分离**：在本机 3060 Ti 上约 25–40 秒 / 首（§19），1 万首约 3.5–4.5 天，只在显卡空闲时可行；在租用的 RTX 4090 48G 上估计 10–15 秒 / 首，约 1.5–2 天（约 100–120 元）。上传原始音频约 80 GB（按每首 8 MB 估）。

**流程**：
- 你能拿到的所有音乐 → 在租用的 GPU 上分离 → 教师集成打伪标签（只取高置信帧）→ 带噪声（增广、dropout）训练更大的学生 → 学生当新教师，迭代 2–3 轮。
- 证据：歌声转录的 noisy student（ICASSP 2022）比普通师生训练更好，同一作者此前的工作约在第 2 轮后不再上升；和弦识别（DAFx 2026）用 1000+ 小时伪标签，最终学生同时超过有监督基线和教师。
- 与 BassFM 自监督预训练（BEST-RQ 掩码预测 + 移调等变一致性）可以叠加：先自监督，再自训练，最后真实数据微调。
- 规则（09-30）允许模型输出当训练标签，前提是评测用独立标签（§1）。

## 4. 各误差源的专项手段

### 4.1 起音 / 切分（A）
- 高时间分辨率的起音前端（hop 64，约 2.9 ms；现在 hop 11.6 ms，低音区 CQT 窗约 1 秒，§12），只进全帧率分支。
- 起音 / 结束时间回归（Kong 等 2021：钢琴起音 F1 94.8% → 96.7%；同音高的新起音会截断前一个音，正好对应同音重复）。
- 起音分成"换音 / 同音重新拨弦 / 休止后"三类，各自一个阈值。有了合成和 DI 的精确标签，才第一次能真正训练这个区分。
- 已上线的候选起音复核（§23）保留，放在最后一层。

### 4.2 分离与串音（B）
- 诊断先行（本机 CPU）：多余 / 漏掉的起音中，有多少与鼓分轨的底鼓同时；错成的音高有多少在吉他分轨里有能量。
- 通用降噪 / 去串音模型**不替换**分离轨：X-LANCE 还原链在 −9 dB 测试中 15 组有 12 组更差（§20）；底鼓与贝斯常同时起音，吉他低音弦与贝斯谐波重叠，按听感优化的模型会抹掉闷音、幽灵音这类弱信号。
- 根本办法是 §5.3 的融合：扒谱分支直接看到鼓和吉他，串音由模型自己判断；联合训练时，分离模型被直接要求"保留扒谱需要的东西"（Jointist：分离与转录联合训练对两者都有提升，前提是转录器先预训练好）。

### 4.3 音高（C）
- 收益主要来自数据扩大和自监督（音色多样性 → 减少"某种音色就判某个八度"的捷径）；频率轴注意力（hFT 式）针对"高一个八度"的真错。
- 标签清洗：信号裁判判定"谱错"的高置信分歧音，在损失里降权或换软标签，不改谱。

### 4.4 技法（F）
- 标签：合成渲染（技法完全已知，MODO 支持滑音 / 揉弦 / 闷音 / slap，Ample 支持击勾弦 / 连音滑 / 手掌闷音）+ DI 回流 + 购买谱（降权）。评测：IDMT（许可只能评测）+ 金标准。
- 模型：技法头 + 以整个音为窗口的逐音分类（TART 式）；滑音另外看细分辨率的音高轨迹。
- 上线规则不变：每类在独立集上精确率 ≥ 0.6 才启用。

### 4.5 指法（G）：先量化"录音能不能听出选弦"
**已有证据**：Abeßer 等在孤立贝斯单音上，弦的识别 F 值 0.93（4 类，CMMR 2012），2017 年的系统在拨弦方式、表情、弦号上都超过 0.88；吉他在更接近实际的条件下弦号只有 82%（DAFx 2014）。物理上的线索：同一音高在较粗的弦、较高的品位上不和谐度不同；空弦与按弦的延音和衰减不同；粗弦更暗。这些线索在**干净 DI 单音**上是存在的，但在压缩、过载、分离之后会明显减弱。所以你的怀疑合理。

**实验（约 1 小时，本机）**：用你的 4 弦和 5 弦琴，选约 20 个音高，每个音高在 2–3 根弦上各弹几次（指弹 / 拨片各一遍），录 DI。然后：① DI 上训练一个小分类器，看能分多准；② 同一批 DI 过箱模、混入伴奏、再分离，看还剩多少。
**决策规则**：
- 某类条件下（例如干净音色、慢速长音）可分辨 → 指法以录音证据为准；
- 不可分辨 → 按可弹性和购买谱的习惯（现有 Viterbi）；
- 实现上，把"弦的音频证据"作为 Viterbi 的一个发射项，权重由它的可信度决定，可信度低时自动退化成现在的行为。
TART（2026）用音频条件的模型分配弦 / 品，Tab F1 比此前最好的基线高 8.5 个点，说明音频信息对指法有用；但那是吉他，而且是在干净录音上。

### 4.6 小节与复合拍（D）
- 节拍 HMM 加入 6/8、5/4、6/4 等状态；加一个"速度层级"分类头。
- 合成数据可以人为造大量 6/8、3/4、变拍号的样本；Lakh MIDI 带拍号信息。
- 节拍 RoPE（§5.4）。

## 5. 架构：放大、融合、测试时计算

### 5.1 模型放大（回答"参数调大点"）
**部署上限**（FP32 推理，估算）：
| 参数量 | 权重 | 16 GB（5080） | 8 GB（3060 Ti） | 每首耗时估计 |
|---|---|---|---|---|
| 100M | 0.4 GB | 轻松 | 轻松 | 数秒 |
| 300M | 1.2 GB | 轻松 | 可以 | 十几秒 |
| 1B | 4 GB | 可以 | 分块推理，与分离模型错开加载 | 数十秒到几分钟 |

每首 1 小时的预算下，耗时不是限制。**真正的限制是数据**：v3–v8 在现有 285 首上已经证明，容量加大不涨分。所以放大要跟着数据走：
1. **规模律小实验**（租卡几十小时）：S/M/L 三个尺寸 × 数据 25%/50%/100%（合成 + 真实）。看仲裁集误差是否随数据和参数稳定下降。
2. 下降 → 继续加数据、放大到 300M–1B；不下降 → 说明瓶颈在别处（标签、域差距），停止放大。

### 5.2 "力大砖飞"的手段清单（按把握排序）
1. **数据规模**：合成 300–1000 小时 + 无标签数千小时（§3.3、§3.5）。
2. **模型规模**：按 §5.1 的规模律逐步放大。
3. **大集成 + TTA**：多个大模型（不同种子 / 数据配比）× 移调 ±1 × 时间伸缩 ±5% × 两三种分离设置（重叠率、不同分离模型）。按项目经验，每多一个模型约 +0.5–1 个全对点，边际递减（§10.6）。
4. **生成 + 验证**（借鉴大模型的"多次采样 + 奖励模型"）：训练一个**验证器**，输入（音频片段，候选音符序列），输出每个音"对不对"的概率。训练数据：合成数据上人为制造的错误（漏音、多音、错八度、错位），以及模型在有标签数据上犯过的真实错误。推理时，对低置信区域枚举 top-k 候选（不同起音阈值、第二音高候选、拆 / 合同音），由验证器 + 声学分数选出最优。
5. **合成校验**（analysis-by-synthesis）：把候选谱用估计出的音色重新渲染，与分离轨逐段比较（已有 `resynth_compare`），对不上的段落回到 4 重新搜索。
6. **自训练迭代**（§3.5）。
7. **最后一步才用强化学习**：金标准集建好之后，以"小节完全一致""合成相似度"为奖励微调解码相关的头（MuScriptor 也是最后用 RL）。必须在金标准上验收，防止对旧标签的噪声过拟合。

### 5.3 分离与扒谱的深度融合（回答"是否彻底内置分离"）
现在是级联：BS-Roformer-SW 先输出贝斯音频 → BassNet 再从音频算 CQT。分离必须先"拍板"出一条音频，判断错了，后面只能靠混音 mel 分支补救；分离模型内部"这一刻哪些能量属于贝斯、哪些属于底鼓"的信息全部丢掉了。融合分三步，每一步都与级联基线做 A/B：

| 步骤 | 做法 | 代价 | 预期 |
|---|---|---|---|
| F1：取中间特征 | 冻结 BS-Roformer-SW，取它贝斯分支（以及共享主干）的中间隐状态，作为扒谱模型的一个输入分支。与 MERT 不同，这些特征是专门为"哪些属于贝斯"训练的，正好是域内的 | 低：不训练分离模型；推理时分离本来就要跑 | 起音、串音类错误下降；若无效，说明分离信息已在输出音频里被充分利用 |
| F2：联合微调 | 分离模型的贝斯路径 + 扒谱模型端到端训练，损失 = 扒谱损失 + 分离损失（保证分离质量不被破坏，伴奏生成功能还要用）；数据：MUSDB/MoisesDB 真实分轨 + 合成混音（干净贝斯已知） | 中：需要租卡，bf16 + 梯度检查点 | 分离"保留扒谱需要的东西"（瞬态、谐波、弱音） |
| F3：一体模型（终态） | 共享的频带切分 RoFormer 主干（用 BS-Roformer-SW 的权重初始化），在混音频谱上运行；输出：6 轨掩码（练习伴奏照常生成）+ 贝斯帧音高 / 起音 / 起音偏移 / 闷音 / 技法 / 弦证据 + 拍 / 强拍；扒谱分支通过交叉注意力读取**所有声部**的频带 token，所以底鼓和吉他是否在响，模型直接知道；上层接全曲尺度的低帧率分支（§5.4） | 高：主要工程量在这里 | 融合收益最大；串音问题被内部吸收，§4.2 的降噪想法以这种形式实现 |

**迭代精修**（在 F3 上）：第一遍扒谱 → 用扒出的音符（谐波模板）给分离做条件（score-informed separation）→ 第二遍扒谱。每首多跑一两遍，在时间预算之内。
**风险**：BS-Roformer-SW 权重的许可（社区权重，自用）；联合训练可能损害分离质量（保留分离损失并监控 SDR）；工程复杂度高，所以必须分步、每步都可以退回级联方案。
**显存**：推理时一体模型 ≈ 现在的分离模型 + 扒谱分支，分离模型本来就在本机运行，所以部署可行；训练放在租用的 80 GB 卡上。

### 5.4 全曲尺度的骨干（Conformer 系）与两个创新点
- 骨干：Conformer 为主线（MusicFM / 2025 AMT 冠军的骨干），E-Branchformer 作对照（小数据和大模型上更稳）。Zipformer 只借鉴多帧率 U 形结构；Mamba、纯解码器 token 模型不采用（理由见第一版：数据量差三个数量级；Windows 上 Mamba 内核支持差）。
- 结构：全帧率（86–100 fps）局部注意力块 → 4 倍下采样的全曲注意力块 → 上采样回全帧率；RoPE（ASRU 2025：在 100–50,000 小时数据上与相对位置编码持平或更好，训练快最多 21%）；起音头只接全帧率分支。
- **节拍 RoPE**：注意力头的维度分为时间组（普通 RoPE）、拍组（角度 2π·k·φ(t)，φ 为连续拍数，k ∈ {1,2,3,4,6,12}）、小节组（2π·k·ψ(t)，k ∈ {1,2}）。注意力只依赖相对拍位，不随速度变化，并能外推到整首。拍点用两遍推理获得；训练时对小节相位加故意的平移，防止错误的强拍"锁死"。先例 RotIE（2026）只用在符号音乐上。
- **自相似偏置注意力**：低帧率分支的注意力加上可学习、初始为 0 的偏置 λ·S（按拍的贝斯音名相似度），让同一乐句里更清楚的那次出现帮助更含糊的那次。与已失败的"硬性统一重复段"不同，它只提示，不改音符。

### 6.2 预算（估计）：本机优先，按档位逐级解锁

**压缩原则**

## 9. 10-22 追加：多次分离、直接输入波形、成绩置信度

### 9.1 "一次算不对就多算几次"：多次分离 + 信道解算

**这个想法对的部分**：把分离模型当成一个有噪声的信道，多次观测再合并，就是集成 / TTA。§5.2 第 3 条已经列了它；它不用训练，是整份计划里最便宜的一项，应该最先测。

**和 MIMO 不一样的两点**：
1. **同一个模型、同一个输入，跑几遍结果都一样。** BS-Roformer-SW 推理时没有随机性，第二遍和第一遍逐个采样点相同。MIMO 的增益来自多根天线、多次接收之间相互独立的衰落和噪声；这里必须人为制造"不同的观测"：
   | 方式 | 做法 | 代价 |
   |---|---|---|
   | 错开分块 | 混音前面补 2.1 / 4.2 / 6.3 秒静音再分离，分块边界落在别处，输出再移回 | 每遍 1 次分离 |
   | 反相 / 左右互换 / 增益 | 输入取反、左右声道互换或整体缩放，输出再变回来；网络是非线性的，所以结果会不同 | 同上 |
   | MC dropout | 推理时打开配置里的 dropout（0.1），每遍换种子 | 同上 |
   | 换模型 | htdemucs_ft、Mel-RoFormer 等；压力测试里 htdemucs_ft 在 −9 dB 明显更差（HANDOVER §18.6），只能低权重 | 需要下载权重 |
   | 移调后分离 | 混音先移 ±1 半音再分离，后验再移回 | 移调本身会引入失真 |
   正式流程的 overlap 8 其实已经是一种"多算几次"：每个采样点被 8 个错开的窗口算过再平均。所以在它之上再加错开分块，收益预计很小；反相、MC dropout、换模型才是新的观测。
2. **分离的错误大多是系统性的。** 底鼓盖住的那个音、和吉他低音弦重叠的那段谐波，每一遍都会以同样的方式出错。设各遍误差的相关系数为 ρ，N 遍平均后误差方差 = σ²·(ρ + (1−ρ)/N)，ρ 接近 1 时多少遍都没用。所以第一步不是合并，而是先测 ρ 和上限。

**信道解算真正能用上的方程**：混音 = 6 个声部之和，这个"信道"是线性的，而且完全已知。在这个约束上能做的有：
- **多通道维纳滤波**（分离领域的标准后处理，Open-Unmix 的 norbert 就是它）：用多遍分离估计每个声部的功率谱和立体声空间协方差，再按混音约束重新分配能量。限制：只有 2 个声道、6 个声源，属于欠定；贝斯和底鼓、人声一样通常居中，空间信息很弱。
- **相位估计**（MISI、Griffin-Lim 类，在"各声部之和 = 混音"的约束下迭代修正相位）：改善的是波形 SDR 和听感。但 **BassNet 输入的是 CQT 幅度（+ 混音 mel），相位在算 CQT 时就被丢掉了**，所以相位修得再好，扒谱看到的东西几乎不变。只有当维纳滤波改变了贝斯频段的幅度（把串进来的底鼓、吉他能量还回去）时，扒谱才会受益。
- 所以顺序是：先测多遍有没有差别 → 有，就先在后验上平均（最简单，等于集成）→ 还有余量，再试维纳滤波。

**"学出来的信道逆"**：如果分离器的失真是系统性的，最有效的办法是让扒谱模型学会它，而不是靠多次平均。这就是 §5.3 的 F1–F3，以及 HANDOVER §22 的老师—学生训练（输入分离轨，标签来自干净贝斯）。

**实验脚本** `bassnet/sep_multi.py`（本机运行，不需要训练）：
```bash
python -m bassnet.sep_multi --set lib --songs 10 --sec 60 \
    --passes base shift1 shift2 shift3 pol swap mcd1 mcd2 mcd3
```
- 曲库 val 歌（原曲，labels_v2）各取 60 秒；`--set musdb` 在 MUSDB test 上以"干净贝斯扒出的音"为参照（SW 可能见过 MUSDB，只作参考）。
- 输出：每一遍的音符 F1；**oracle_R**（至少有一遍扒对的参考音比例，任何合并或挑选方法的上限）；**miss_jacc**（各遍漏掉 / 扒错的音的平均重合度，1 = 每遍错的完全一样）；两种合并：波形平均（`wave_mean`）、后验平均（`post_mean`）；以及多遍一致率作为置信度的 AUC（§9.3）。
- 估计耗时：10 首 × 9 遍 × 60 秒，约半小时（未实测）。
- **判定**：oracle_R 比最好的单遍高不到 1 个点、miss_jacc > 0.8 → 多次分离到此为止。post_mean 在 ≥ 20 首上按配对 bootstrap（§9.3）稳定提高 ≥ 0.5 个点 → 放进正式流程，每首多花 K × 30 秒左右，在 1 小时预算内。oracle_R 明显高于 post_mean → 平均不够，需要按音挑选，交给 §5.2 第 4 条的验证器。

### 9.2 能不能直接输入完整音频，而不是 CQT

"完整音频"可以指三件事，分开回答：

**(a) 原始波形代替 CQT：可以做，但不建议替换，建议增加。**
- CQT（加谐波堆叠）是人为加入的先验：频率轴取对数，移调就是平移，所以卷积核在所有音高上共享，±3 半音移调增广和移调 TTA 都靠它；谐波堆叠把基频和泛音对齐到同一位置。波形前端（可学习滤波器组如 SincNet / LEAF，或 wav2vec 式卷积编码器）必须从数据里自己学会这些。在音高类任务上，可学习前端一般只能追平好的固定变换，很少明显超过，除非数据量很大。
- 项目里已经有一次相关证据：MERT（3.3 亿参数、直接读波形的基础模型）作为额外分支加进来，没有实质提升（HANDOVER v6m）。
- **CQT 确实丢掉的东西**，也是加波形分支的理由：
  1. **低音区时间分辨率差**：3 bin/半音时 Q ≈ 51；librosa 的 CQT 窗长 ≈ Q / f，E1（41 Hz）约 1.25 秒，B0（31 Hz）约 1.7 秒。基频那一带的起音被抹得很宽，起音判断主要靠高次谐波；分离把高频弄钝时（平滑弦、闷音），起音就更难判断。
  2. **相位**：同音重复拨弦时能量可能没有峰，但拨弦会让相位重新开始。HANDOVER §23 的损耗审计里，漏掉的音有一部分正是"同音重复拨弦根本没有峰"。
  3. 22.05 kHz 单声道：slap / pop 的 11 kHz 以上亮度和立体声信息丢失（stems6 有 44.1 kHz 立体声）。
- **建议做法**：保留 HCQT 主干负责音高，加一个专门负责起音的分支，二选一做 A/B：
  - 便宜版：短窗 STFT 幅度 + 相位导数特征（瞬时频率偏差、群延迟），直接拼进现有输入；
  - 完整版：在 44.1 kHz 分离轨波形上用一维卷积前端降到 86 fps，与 CQT 分支拼接。
  - 验收看起音 F1，以及单独统计"同音重复"这一类音的召回率。
- **注意**：波形分支不能随 CQT 一起做移调增广（和 MERT 一样，移调样本要把这个分支置零，或在波形上真正移调）。

**(b) 输入混音而不是分离轨**：现在已经有混音 mel 分支。完整形态是 §5.3 的 F3：一体模型在混音的复数 STFT（实部 + 虚部，相位也在里面）上运行，所以 F3 本身就是"直接输入完整音频"的终态。

**(c) 输入整首歌而不是 10 秒片段**：§5.4 的全曲尺度骨干。

### 9.3 每次成绩的置信度

这里有两个不同的问题。

**(a) 测试集上的一个分数（比如音符 F1 0.833）本身有多准**
- **抽样单位是歌，不是音。** 同一首歌里的音不独立（同一个混音、同一个分离错误、同一个乐句重复 20 次），按音算误差条会窄得离谱。正确做法是按歌重抽样（bootstrap）：从 n 首歌里有放回地抽 n 首，算一次分数，重复 1 万次，取 2.5% 和 97.5% 分位。
- **量级**（假设，需用真实数据核对）：55 首、每首 F1 的标准差 0.08 时，标准误 ≈ 0.08 / √55 ≈ 1.1 个点，95% 区间约 ±2 个点。也就是说，单独报"0.833"时，真实水平大约在 0.81–0.85 之间。
- **比较两个版本要配对**：两个版本在同一批歌上跑，难歌两边都难，这部分会抵消。对每首歌的差值做 bootstrap，区间通常比单个分数的窄好几倍（模拟：每首差值的标准差 1.2 个点时，55 首的 95% 区间约 ±0.3 个点）。所以 HANDOVER 里那些 0.3–0.5 个点的改进，单看两个均值看不出真假，配对后可能是显著的。
- **还要加上训练种子的波动**：bootstrap 只反映"换一批歌"的波动，反映不了"换一个种子重训"的波动。§1.4 已经规定：差值既要超过 2 倍种子标准差，配对区间也要不跨 0。
- **bootstrap 管不到的**：参考谱本身有错（§1.1：分歧里裁判支持模型 74%）。这是偏差，不是随机误差，抽样再多次也消不掉，只能靠金标准（§1）。
- **多次比较**：在测试集上试 20 个变体、挑最好的那个报告，这个分数一定偏高。变体在 val 上选，test 只做一次确认。

工具 `bassnet/score_ci.py`（`song_eval` 现在会顺带存每首的命中数和音符数，可以算按全部音合计的 F1）：
```bash
python -m bassnet.score_ci prod_1001                      # 每项指标：均值、95% 区间、标准误
python -m bassnet.score_ci prod_0929 prod_1001 --split test   # 配对：差值区间、P(B>A)、变好 / 变差首数、符号检验
python -m bassnet.score_ci --seeds v11_s1 v11_s2 v11_s3       # 种子标准差
```

**(b) 一首新歌没有答案时，能不能估计这次扒谱的分数**
可以，分三步：
1. **逐音"对的概率"**：现有信号有模型自己的把握 min(conf, 起音峰值)（已用于低置信标记：标出 4.4% 的音，其中 69% 有错）、起音复核器的概率（`onset_rescore`）、集成成员和移调 TTA 之间的一致率、多遍分离的一致率（§9.1，`sep_multi` 直接给出它的 AUC）、重合成相似度（`resynth_compare`）。用 val 歌把这些拼起来拟合一个校准器（逻辑回归或保序回归），在 test 上用可靠性图检查"说 80% 对的音，是不是真的约 80% 对"。
2. **合成每首的预期分数**：预期命中 H = Σ（写出的每个音对的概率）；预期漏音 M = Σ（被拒掉的候选起音其实是音的概率）+ 连候选都没有的漏音（按 val 上的比例补）；预期 F1 ≈ 2H / (写出的音数 + H + M)。同样的方法可以用在小节级（预期全对小节比例）。
3. **给区间：保形预测**（conformal prediction）：在 val 歌上算"实际 F1 − 预期 F1"的绝对值，取 90% 分位 q；新歌报"预期 F1 ± q"。只要新歌和 val 歌来自同一类分布，这个区间就有 90% 的覆盖率，不依赖任何分布假设。曲风差得远的歌（结束バンド、DI 录音）不保证，要用金标准集检查实际覆盖率。

验收：在 test 上，预期 F1 与实际 F1 的秩相关 ≥ 0.7，90% 区间的实际覆盖率在 85–95% 之间。达到之后才能把分数显示在软件里，而且按 `AGENTS.md` 只显示一个数或一个色点，低置信小节继续用谱面上已有的虚线框。
