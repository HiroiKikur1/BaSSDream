# 扒谱准确度提升计划（误差账本 → 提升手段 → 架构 → 租卡执行）

2026-10-20。只有理论分析和计划，没有做任何训练或评测，也没有改代码。项目内的数字都出自 `docs/HANDOVER.md`（标注了节号）；凡是"估计 / 预计"的数字都没有实测过。

**约束（用户 10-20 确认）**
- 训练：租卡，算力不是约束。
- 部署：最终模型要能在 16 GB 显卡（典型 5080）上以 FP32 全精度推理，在现有 8 GB 显卡（3060 Ti）上能用。
- 目标：准确度做到最高。按 §18 的约定，"准确"指**忠于录音**，参考谱不再是唯一标准。

---

## 0. 结论先行

1. **真实误差最大的一项是音符切分（起音），不是音高。** 唯一一份标签与演奏完全一致的真实数据（IDMT 真实 DI 贝斯线）上，音符 F1 只有 0.845，而匹配上的音音高对了 96.8%（§20）。对照参考谱的音高"错误"里，约 3/4 其实是谱写错了（§17.4）。
2. **第二大误差源是分离，而且之前低估了。** 用加法合成的贝斯测，分离只损失约 1 个点（§17.5）；但在 MUSDB 真实多轨上，分离轨与干净贝斯轨扒出的音符一致率只有 F1 0.8275（§21），贝斯被埋 9 dB 时降到 0.81–0.93（§18.6）。合成音色太容易分离，那个"上限"过于乐观。
3. **"没输出"的部分比"输出错"的部分更大**：约 8–10% 的音带有技法记号（滑音、闷音、击勾弦、slap/pop），目前只输出 slap（§11.10、§21）；指法与真实演奏者同弦的只有 72%（§20）。这两项一旦计入"谱是否准确"，就是排在切分之后的最大缺口。
4. **现有评测已经测不出进步。** 参考谱本身的误差和模型误差在同一个量级上，再提升 1–2 个点在旧标签上看不出来，甚至可能显示为下降。**第一步必须是建金标准集和独立仲裁集**（§1），否则后面所有投入都无法验证。
5. **最大的提升杠杆是数据，不是架构。** 按预期收益排序：① 带精确标签的大规模合成数据（DadaGP 渲染、真实音色、混入真实伴奏）；② 域内自监督预训练（无标签贝斯轨，数量不限）；③ 面向扒谱目标训练分离模型；④ 用户 DI 录音回流。架构升级（Conformer 系）的作用是**承载**这些数据，单独换骨干预计不涨分（§4.1）。
6. **用降噪 / 去串音模型处理分离轨（用户 10-20 提议）**：通用模型直接替换分离轨，大概率有害。X-LANCE 还原模型已实测变差（§20）。原因是摇滚里贝斯与底鼓经常同时起音，吉他低音弦又和贝斯的谐波重叠，去串音会把贝斯自己的起音和谐波一起削掉。更可能有效的是：把鼓、吉他分轨作为**额外输入**交给模型，让模型自己判断哪些是串音；或者用扒谱损失训练专门的去串音模型（§3.3a）。**先用一个只需 CPU 的诊断量出串音到底占多少误差**。
7. **部署约束基本不起限制作用**：一个 1 亿参数的模型 FP32 推理只需约 0.4 GB 权重，整首歌推理在 3060 Ti 上估计是秒级（§5.4）。所以可以直接部署大模型，蒸馏只是可选的提速手段。

## 1. 先修尺子：准确度怎么量

### 1.1 现有尺子的问题
- 参考谱 = 雪鹽子的购买谱。模型与谱在音高上的分歧里，信号裁判支持模型 74%、支持谱 19%、不确定 8%（§17.4）；模型判"低一个八度"的音里 95% 录音中确有低八度证据（§11.13）；同一录音的两份人工谱，忠实版之间一致率 95–100%（§11.11）。
- 结论：**对照参考谱的天花板大约就在 90–95% 附近**，而当前系统已经接近它。在这把尺子上，"真的变好"和"更贴近谱的写法习惯"无法区分。

### 1.2 新尺子（三层，按可信度排序）

| 层 | 内容 | 标签来源 | 成本 | 用途 |
|---|---|---|---|---|
| 金标准集 | 10–20 首曲库歌，用户在核对版里逐段审核（`edits.jsonl` 的 review 区间） | 人耳 + 录音 | 用户每首约 0.5–1 小时 | **最终裁判**；只做评测，永不训练 |
| 独立仲裁集 | IDMT 真实 DI（17 条，§20）；MUSDB test 干净贝斯（50 首，§21）；用户 DI 录音（见 §3.4）；合成渲染（标签 100% 正确） | 演奏 / 渲染本身 | 低 | 架构和数据的对比 |
| 参考谱集 | 现有 55 首 val/test + labels_v2 | 购买谱 | 已有 | 回归保护：不能明显变差 |

### 1.3 统计规则
- 先用当前配方跑 3 个种子，得到种子间波动。"有提升"= 差值超过 2 倍标准差，**并且**按歌曲配对的 bootstrap（10,000 次）95% 置信区间不跨 0。
- 每个指标都按误差类型拆开报告（§2 的各行），不只报总 F1。

### 2.2 从账本得出的判断
1. **A + B 合起来是"音符对不对"的主体**，而且彼此叠加：分离把起音的瞬态和低频能量弄糊，切分就更难。
2. C（音高）已经接近测量噪声；继续在它上面投入，收益会很难看到。
3. F、G 是"谱能不能直接用"的主要缺口。它们缺的不是模型，**是带标签的数据**：购买谱里技法标记不一致（§22），弦 / 品是扒谱者自己的选择，不一定是录音里的实际弹法。
4. D 的剩余问题是结构性的（复合拍），数据里这类歌很少。

## 3. 提升手段（按 预期收益 × 把握 排序）

### 3.1 【前提】金标准集与仲裁集（§1.2）
没有它，下面每一项都无法验收。可以和 3.2 并行准备。

### 3.2 大规模合成数据：标签 100% 正确，同时覆盖 A、F、G
**做法**：把符号谱渲染成贝斯音频，再混进真实伴奏。
- 谱的来源：DadaGP（2.6 万份，含贝斯轨与技法标记，等授权，§19）；没有 DadaGP 时，先用用户的 338 份购买谱，但它们和训练歌是同一批曲子，多样性有限。
- 音色：采样型贝斯音源（每根弦单独录音，**弦 / 品信息就会体现在音色里**）× 拨弦方式（指弹 / 拨片 / slap）× 放大器与效果器模拟（Neural Amp Modeler 一类的真实采样）× 随机电平（包括 −12 到 0 dB 的"被埋"）。
- 伴奏：曲库 6 轨分离里去掉贝斯的部分（`lib_<md5>_rest.npy`，§21 已有 240 首），以及 MUSDB/MoisesDB 的真实分轨。
- 技法按谱面标记真实地渲染：滑音的音高轨迹、击勾弦的弱起音、闷音、泛音、slap/pop 的瞬态。

**证据**：SynthTab（ICASSP 2024，用 DadaGP 渲染吉他）在**所有**同数据集和跨数据集的实验里，先用合成数据预训练、再用真实数据微调都更好，而且对弦 / 品的收益比对音高更明显，说明合成数据教会了模型音色与弦的关系。MuScriptor（2026）也是"合成预训练 → 真实微调 → RL"这一流程。

**风险**：合成与真实的域差距。§17.5 的教训是加法合成太"干净"，所以音色和混音必须尽量真实，而且**只用来预训练**，最后一定用真实数据微调，并在仲裁集上验收。

**预期**：A（切分）、F（技法）、G（指法）是收益最大的三项；音高收益小。

### 3.3 面向扒谱目标的分离（针对 B）
§21 失败的方案是"以干净分轨为目标精调分离模型"，与扒谱的需求不一致。改为：
- **扒谱损失回传**：分离模型（BS-Roformer-SW）后面接冻结的 BassNet，损失 = 对分离输出扒出的帧音高 / 起音，相对于干净贝斯上扒出的结果（或合成数据的真值）。只更新分离模型的贝斯头。Jointist（2023）证明分离和转录联合训练对两者都有提升，前提是转录器先预训练好（从零联合训练反而更差）。
- **训练数据**：MUSDB 100 + MoisesDB 236 首真实分轨 + 3.2 的合成混音（被埋、失真）。
- **另一条路**（已在准备，§22）：不改分离，让 BassNet 学会从分离后的音频里还原干净贝斯能听出的音（老师—学生）。两条路可以叠加。
- 租卡后，BS-Roformer 全模型精调的显存不再是问题（本机此前只能训掩码头，§21）。

**预期**：混音密集、贝斯被埋、过载 / fuzz 的歌收益最大；对 IDMT 这种干净 DI 没有影响。

### 3.3a 降噪 / 去串音处理分离轨（用户提议）

**已有证据**
- X-LANCE MSR 2025 冠军的还原链（降噪 → 去混响，均为 RoFormer）：−9 dB 压力测试 15 组里 12 组更差、0 组更好，音符 F1 0.806 vs BS-Roformer-SW 0.865（§20）。
- 社区的去串音模型（例如 UVR 模型列表里 unwa 的 "Bleed Suppressor"、各类 Mel-RoFormer 降噪模型）**还没测过**。它们没有公开的训练细节和基准；Mel-RoFormer 原论文也指出，它的梅尔频带划分对贝斯的效果不如 BS-RoFormer 的频带划分。
- MSR 挑战赛按"听感"打分（Multi-Mel-SNR、MOS），不按扒谱准确度打分。

**为什么通用降噪容易帮倒忙**
1. **底鼓与贝斯同时起音**：在摇滚里，底鼓和贝斯的重音大量重合。去串音模型分不清这一刻的瞬态属于谁，削掉底鼓的同时也削掉了贝斯的拨弦瞬态，而这正是起音检测（误差 A）最需要的信号。
2. **吉他与贝斯的谐波重叠**：吉他低音弦的基频落在贝斯的 2–4 次谐波上。BassNet 的谐波堆叠正好用这些谐波判断音高（尤其是 5 弦低 B 基频弱的时候，§9.7），一起被削掉就会让八度判断更差。
3. **按听感优化**：听感上"干净"意味着抹平弱信号，而闷音、幽灵音、拨片噪声恰恰都是弱信号。

**更可能有效的做法（按先后）**
1. **诊断（只需 CPU，先做）**：在 55 首 val/test 上统计：
   - 多余起音里，有多少落在鼓分轨底鼓 / 军鼓起音的 ±20 ms 内；
   - 音高错误里，有多少错成的音高在吉他 / 其他分轨里有明显能量；
   - 漏掉的起音里，有多少与底鼓同时（被当成串音一起压掉）。

   用 `stems6` 的现成分轨即可，不需要训练。如果这几类加起来只占误差 B 的一小部分，就不值得在去串音上投入。
2. **把"串音来源"作为模型输入，而不是在音频上删掉它**：BS-Roformer-SW 一次分离本来就输出 6 轨。把鼓分轨的低频起音包络（底鼓 / 军鼓频带）、吉他 + 其他分轨的 CQT（下采样到较少的通道）作为新的输入分支。模型可以学到"这个起音与底鼓同时，但贝斯频带里的谐波没有重新激发，所以是串音"。推理时几乎没有额外成本。训练数据用 §3.2 的合成混音最理想，因为串音多少是已知的。
3. **信号级的"纯度图"（无需训练，可以快速 A/B）**：每个 CQT 格计算 贝斯功率 / 6 轨功率之和，类似 Wiener 掩码的一致性检查，**作为额外的输入通道**，不替换原分离轨。
4. **如果要试现成的去串音模型**：只能作为与原分离轨并行的第二路输入，绝不能替换；并且以扒谱指标（−9 dB 压力测试、MUSDB 分离轨 vs 干净轨）来选，不看听感。考虑到 X-LANCE 的结果，先验预期偏低，但测一次的成本很低。
5. **面向扒谱的去串音 = §3.3 的扒谱损失回传**：去串音模型（或分离模型的贝斯头）后接冻结的 BassNet，用扒谱误差训练。这是这个想法最有原理依据的版本：模型被直接要求"去掉会让扒谱出错的东西，保留扒谱需要的东西"。

### 3.4 用户 DI 录音回流（A、G 的真实数据）
- 演奏评测已经把每次录制存进 `performance_takes`，并给出逐音判定（§14、§22）。判为 PERFECT / GREAT 的音 = 用户确实按谱弹出的音，**弦 / 品已知，时间精确到毫秒**，是真实电贝斯 DI 的高精度标签。
- 只取判定好的音段作为训练标签，其余部分在损失里屏蔽。按歌曲划分，严格避开 val/test 和金标准集。
- 这是目前公开数据里几乎空白的东西（真实贝斯 DI + 弦 / 品标注，§8.1；2025–2026 年新出的 GOAT、Guitar-TECHS 都是吉他）。

### 3.5 域内自监督预训练 BassFM（A、C，提升鲁棒性和校准）
- 数据：所有能拿到的音乐，先分离出贝斯轨（无需谱），可以做到数千小时。
- 目标：BEST-RQ 掩码预测（MusicFM 的做法），加上移调等变一致性（PESTO 的思路：CQT 平移 k 格，帧音高输出也要平移 k 类），可选加入高置信教师伪标签。
- 对 MERT 无效（§11.11）的回应：MERT 是在混音上训练的、冻结后做 PCA、75 Hz、移调样本只能置零；BassFM 在这四点上都不同。但这个反例仍然是风险，预期收益保守估计为 0–2 个点。

### 3.6 起音专项（针对 A）
- **高时间分辨率的起音前端**：分离轨短窗 STFT（hop 64，约 2.9 ms）或原始波形步长卷积，只送进全帧率分支。现在的 hop 是 11.6 ms，低音区 CQT 的窗口约 1 秒（§12），重复拨弦的瞬态被抹平了。
- **起音 / 结束时间回归**（Kong 等，2021）：每帧回归到真实起音的距离，得到亚帧精度。在钢琴上起音 F1 从 94.8% 提到 96.7%。他们的做法里，同音高出现新起音时会截断前一个音，这正好对应同音重复。
- **显式的音符状态**：把"起音"细分为"换音起音 / 同音重新拨弦 / 休止后起音"，各自一个输出与阈值（§7 P1 的老想法，现在有了 3.2、3.4 的精确标签，可以真正训练）。
- 已上线的候选起音复核（§23）保留，作为最后一层。

### 3.7 技法（针对 F）
- 标签：3.2 的合成渲染（技法完全已知）+ 3.4 的 DI 录音 + 购买谱（降权，因为标记不一致）。评测用 IDMT（许可只能评测）。
- 模型：大模型的技法头 + TART 式的逐音分类（以整个音为窗口，不只看起音帧）；滑音另用细分辨率音高轨迹检测（§23 已发现，谱里的"音尾下滑"约 80% 紧接下一个音，从声音上很难区分，所以必须有精确标签）。
- 部署策略不变：每类技法只有在独立集上精确率 ≥ 0.6 才启用。

### 3.8 指法（针对 G）：加入音色信息
- 同一个音高在不同弦上的音色不同（不和谐度、开放弦的延音、频谱包络），老的贝斯研究（Fraunhofer，用 SVM）和吉他研究（Bastas 等用不和谐度，ICASSP 2022）都证明可以从音频估计弦。现在的指法只看符号，完全没用到这些信息。
- 做法：每个音一个"弦的音频证据"分数，作为现有 Viterbi 的发射项（与可弹性约束结合）。TART（2026）用音频条件的 T5 做弦 / 品分配，弦 / 品 Tab F1 比此前最好的基线高 8.5 个点。
- 标签：3.2 的分弦采样渲染、3.4 的 DI 录音（弦 / 品已知）。
- 注意：对用户来说，"指法准确"有两种含义：与录音里的实际弹法一致，或者与好弹的习惯一致。两者冲突时怎么取舍，需要用户定（§7）。

### 3.9 小节与复合拍（针对 D）
- 在节拍 HMM 里加入复合二拍（6/8）和 5/4、6/4 等状态；增加一个"速度层级"分类头（§10.8 的老想法）。
- 数据：3.2 的渲染可以人为生成大量 6/8、3/4、变拍号的样本；DadaGP 有拍号信息。
- 结构上配合 §4.3 的节拍 RoPE。

### 3.10 标签清洗与带噪学习
- 用信号裁判（§17.4）给分歧音打分，**高置信"谱错"的音在损失里降权或换成软标签**，不直接改谱。
- 带噪对齐的研究可以借鉴：NoteEM（ICML 2022）同时训练转录器和对齐（本项目的 labels_v2 本质上是同一思路）；2025 年的 "Count the Notes" 指出 DTW 对齐会引入同步误差，改用直方图式的弱监督。只有在以后引入未对齐的社区谱时才需要它。

### 3.11 集成、蒸馏与最后的直接优化
- 租卡训练多个大模型（不同种子 / 不同数据配比）组成教师集成，按 §10 的经验，这类集成每多一个模型约 +0.5–1 个全对点，边际递减。
- 部署：直接部署集成，或蒸馏成一个学生模型（见 §5.4，部署约束很宽松）。
- 金标准集建好之后，可以考虑 MuScriptor 式的强化学习：以"小节完全一致""重合成相似度"作为奖励，只微调解码相关的头。**必须在金标准集上验收**，否则会对旧标签的噪声过拟合。

## 4. 架构（服务于 §3 的数据）

### 4.1 为什么要换、预期是什么
- 项目里已有充分证据表明，在现有数据上换骨干不会涨分（v3–v8、MERT、全曲上下文 Transformer 都收敛在同一水平，§11.11、§15、§17.7）。所以**在现有 285 首数据上，单独换 Conformer 的预期是 ±1 个点**。
- 换骨干的必要性来自 §3：合成数据加自监督能把训练数据扩大一两个数量级，GRU（约 3.4M 参数，10 秒切片）装不下，也看不到整首歌。
- Conformer 系的三个结构优势：全曲尺度的注意力（整段八度、半小节相位）；按拍计的位置编码；有成熟的大规模自监督配方（MusicFM 就是 BEST-RQ 训练的 Conformer，2025 AMT 挑战赛冠军用它做编码器）。

### 4.2 候选架构

| 架构 | 证据 | 判断 |
|---|---|---|
| **Conformer**（U 形多帧率 + RoPE） | 2025 AMT 冠军的骨干；MusicFM 25 Hz 版拍 F1 0.868、强拍 0.804、和弦 0.714 | **主线** |
| **E-Branchformer** | 20 个基准上与 Conformer 持平或更好，大模型、小数据上训练更稳 | **主线的对照组**，第一轮两条一起跑 |
| Zipformer | 比 Conformer 快 50% 以上、显存更少 | 只借鉴多帧率 U 形结构；它的收益部分依赖专用优化器 ScaledAdam，移植成本高 |
| 频率–时间交替注意力（Beat This、hFT-Transformer） | 节拍与钢琴转录上表现好 | 作为前端插件：沿音高轴的注意力直接比较各候选八度，针对 C 中"高一个八度"的真错 |
| Mamba / 混合 | 语音上与 Conformer 互有胜负 | 不采用：优势在速度和超长序列，本项目不缺；Windows 上内核支持差 |
| 纯解码器 token 模型（MuScriptor、MT3） | 需要数十万首数据 | 不采用：YourMT3+ 实测远不如 BassNet（§11.11），而且不保证写出合法的谱 |

### 4.3 结构（输出接口与现模型完全一致，`decode`、`pipeline`、评测都不用改）

```
CQT ─► 谐波堆叠 + 卷积（保留，沿音高方向近似等变）─► [可选] 音高轴注意力插件
混音 mel、分离轨宽频分支、[新] 高分辨率起音前端（hop 64）
      └─► 投影 ─► [A] 全帧率块（86 fps，局部注意力）─► 下采样 ×4
               ─► [B] 低帧率块（21.5 fps，全曲注意力 + 节拍 RoPE + 自相似偏置）
               ─► 上采样 + 跳连 ─► [C] 全帧率块 ─► 帧音高（保留 per-pitch 局部旁路）/ 起音 + 起音偏移回归 / 闷音 / 拍 / 强拍 / 技法 / [新] 弦证据
```

- 块配置：Macaron FFN（SwiGLU）、前置 RMSNorm、RoPE（ASRU 2025：在 100–50,000 小时的数据上与相对位置编码持平或更好，训练快最多 21%，兼容高效注意力）、深度卷积核 15、随机深度 0.1、中间层辅助音高损失（与 InterCTC 原理相同，低资源下是有效的正则）。卷积模块里用 LayerNorm/GroupNorm 代替 BatchNorm，避免小批量长切片下统计量不稳。
- 起音头只接全帧率分支，绝不从低帧率分支上采样。
- 切片 30–60 秒；推理时 [B] 看整首歌（或者用 FastConformer 的"局部注意力 + 全局 token"）。

### 4.4 创新点一：节拍 RoPE
- 每个注意力头的维度分三组：时间组（普通 RoPE）；拍组，角度 2π·k·φ(t)，φ 是连续拍数，k ∈ {1, 2, 3, 4, 6, 12}；小节组，角度 2π·k·ψ(t)，ψ 是连续小节数，k ∈ {1, 2}。于是注意力只依赖相对拍位，不随速度变化；因为是周期函数，训练用 30 秒切片也能外推到整首歌。
- 先例：RotIE（2026）把 RoPE 推广到小节内位置等属性，用在符号音乐生成上，长序列上收益最明显。**用估计出的拍点去驱动音频帧上的 RoPE，目前没有看到先例。**
- 拍点来源：两遍推理（第一遍置零拍组 / 小节组 → 现有 `song_beats` → 第二遍）。训练时用真实拍点加 ±20 ms 抖动；20% 置零；15% 用第一遍的预测拍点。
- 最大风险是错误的强拍相位被小节组"锁死"：训练时 10% 的样本故意把 ψ 平移 1–2 拍，强拍监督保持真值，迫使模型在冲突时相信声学证据。若加小节组反而变差，就只保留拍组。

### 4.5 创新点二：自相似偏置注意力
- 低帧率分支的注意力 logit 加上 λ_h · S(拍(t), 拍(s))，S 是按拍同步的贝斯音名分布的余弦相似度（z 分数），λ_h 每个头一个、初始化为 0。
- 与已失败的"重复一致性 / 规整"不同，它不硬改音符，只提示"哪里可能是同一乐句"，让同一乐句里更清楚的那次出现帮助更含糊的那次。
- 风险：把错误传染给所有重复段。必须看逐首的分布。

### 4.6 规模
| 版本 | 配置 | 参数 | 用途 |
|---|---|---|---|
| S | d=192，2+4+2 块 | 约 5M | 在现有数据上与 GRU 对照（隔离"结构"的影响） |
| M | d=256，2+6+2 块 | 约 13M | 合成 + 真实数据 |
| L | d=512，2+12+2 块，前端 64 通道 | 约 100M | BassFM 预训练 + 全部数据；教师 |

## 5. 资源估算（均为估算，未实测）

### 5.1 训练显存（每帧保存的激活）
- M 版：前端约 5 万个浮点数 + 全帧率 4 块约 3.5 万 + 低帧率 6 块约 1.2 万 ≈ 每帧 10 万，FP32 约 0.4 MB。30 秒切片 × batch 16 ≈ 4.1 万帧 ≈ 17 GB。
- L 版：约每帧 21 万个浮点数，FP32 约 0.85 MB；30 秒 × batch 16 ≈ 35 GB。A100/H100 80 GB 上没有问题。租卡训练可以用 bf16，部署时再用 FP32 推理（权重是同一份）。

### 5.2 训练计算量（L 版，粗估）
- 每秒音频约 30 GFLOP（前向 + 反向，含前端卷积）。1000 小时数据一个 epoch 约 1.1×10¹⁷ FLOP，按 A100 有效 100 TFLOPS 算约 20 分钟。即使 50 个 epoch，也只要十几个 A100 小时。
- **真正的成本在数据准备**：分离数千首歌、渲染合成数据（CPU 为主）。分离在本机每首 25–40 秒（§19），在租用的 A100 上估计更快。
- 合计估计在数十到一两百 A100 小时的量级。以第一次实际跑出的速度为准，再修正预算。

### 5.3 本地部署（推理，FP32）
| 模型 | 权重 | 整首歌（约 2 万帧）推理 | 16 GB（5080） | 8 GB（3060 Ti） |
|---|---|---|---|---|
| M（13M） | 0.05 GB | 估计 < 1 秒 | 可以 | 可以 |
| L（100M） | 0.4 GB | 估计数秒（约 2–3 TFLOP） | 可以 | 可以（与分离模型错开占用显存，或分块推理） |
| L × 3 集成 × 移调 TTA ×3 | 1.2 GB | 估计数十秒 | 可以 | 可以（逐个加载） |

### 5.4 结论
部署约束对 L 版及其集成都不构成限制。分离模型（BS-Roformer）本来就在本机运行，扒谱模型与它按顺序占用显存即可。

## 6. 执行阶段（每阶段：快照 → 新尺子评测 → 对比谱 → 用户认可后替换正式版）

| 阶段 | 内容 | 主要资源 | 验收 |
|---|---|---|---|
| P0 | 金标准集（10–20 首核对版审核）；仲裁集整理；按种子测出噪声带；评测按误差类型拆分；**串音诊断**（§3.3a 第 1 步） | 用户时间 + 本机 CPU | 尺子就绪；知道串音占误差 B 的多少 |
| P1 | 合成数据管线：音色库（分弦采样、拨弦方式、放大器模拟）、技法渲染、混入真实伴奏；先用 338 份购买谱，DadaGP 授权后扩到全量 | 租 CPU 为主 | 抽听；渲染的标签回读与原谱逐音一致 |
| P2 | 大规模分离：所有可用音乐 → 贝斯轨（供 BassFM） | 租 GPU | — |
| P3 | 架构对照：Conformer-S、E-Branchformer-S vs GRU，在现有数据上各 3 个种子 | 租 GPU，少量 | 不退步，且同音重复召回或仲裁集上更好 |
| P4 | BassFM 预训练（L 版）→ 合成数据预训练 → 真实数据微调，与随机初始化对照 | 租 GPU | 仲裁集 + 金标准集同时提升 |
| P5 | 面向扒谱的分离精调；老师—学生；串音来源作为输入、纯度图（§3.3a），按诊断结果决定做不做 | 租 GPU | MUSDB 分离轨 vs 干净轨的一致率；−9 dB 压力测试 |
| P6 | 起音专项（高分辨率前端、偏移回归、音符状态）；技法头；弦证据 + 指法 | 租 GPU | 分项指标；技法精确率 ≥ 0.6 才启用 |
| P7 | 节拍 RoPE、自相似偏置、复合拍解码 | 租 GPU | 小节线、首小节、复合拍歌曲 |
| P8 | 集成 / 蒸馏；3060 Ti 与 5080 上的部署检查（FP32、耗时、显存）；GP8 实机截图 | 本机 | 五维评测 + 金标准集 |

**可证伪的预期**（写在这里以便事后核对）：
- P3：与 GRU 的差距在 ±1 个点以内。若明显更好，说明之前"GRU 不是瓶颈"的判断要修正。
- P4：收益主要出现在仲裁集（DI、MUSDB）和切分类指标上；参考谱集上可能只有小幅变化。
- P5：收益集中在贝斯被埋 / 失真的歌。
- P6：技法从"基本没有"变成可以启用 2–3 类；指法与真实演奏者的同弦率从 72% 明显上升。
- 若 P4、P5 都没有提升，说明瓶颈在真实数据的标签质量，资源应全部转向金标准集和 DI 录音回流。

## 7. 需要用户决定的事项
1. **金标准集**：选哪 10–20 首（建议覆盖：同音重复多、贝斯被埋、失真、5 弦、6/8、slap 多的歌各几首）；每首约 0.5–1 小时的核对时间。
2. **DadaGP 授权**：申请状态（§19 仍在等作者回复的链接）。没有它，合成数据的多样性有限。
3. **贝斯音源**：合成数据的质量取决于采样音源（分弦录音的商业音源最好），以及是否购买 / 使用某些音源和放大器采样。
4. **指法的标准**：与录音里的实际弹法一致，还是与"好弹 / 雪鹽子的习惯"一致？两者冲突时以哪个为准？
5. **DI 录音回流**：是否同意把练习录音（只取判定好的音段）用作训练数据。
6. **租卡预算**：§5.2 估计在数十到一两百 A100 小时的量级，先租一小段时间实测速度再定。
