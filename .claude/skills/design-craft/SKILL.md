# 设计学总纲

这份总结的来源：经典理论（Albers、Itten、notan、格式塔、Müller-Brockmann、Bringhurst、Tufte）、日本游戏和平面设计的行内经验（跳跃率、PCCS 色调、袋文字、和欧混植、母题技法），以及一次长期改稿中用户一轮轮否掉方案时留下的经验。

它不讲"什么风格好看"，讲的是**为什么好看、为什么难看、怎么查、怎么改**。

## 怎么用

1. **动手前**先读"一、总纲"和"二、诊断词典"；涉及哪个领域，再读对应的 `references/`。
2. **做设计**照"三、流程"走：先有明暗结构，再上颜色，最后做细节；每一步都要渲染出图看。
3. **交付前**过"四、清单"，再跑 `tools/notan.py` 和 `tools/contrast.py`。
4. **项目有自己的品牌语言时**，以项目文档为准；这里只提供原理和方法。

## 一、总纲：十二条

1. **明暗是骨架。** 把画面模糊、压成黑灰白三阶，必须还看得出一两块大形和一个焦点。颜色、细节、文字都挂在这副骨架上。骨架不成立，再多细节也是一团。
2. **颜色是关系，不是色值。** 同一个颜色换个底，看起来就是另一个颜色（Albers）。主色要靠深底或满色图来借亮度；放在淡色上一定发灰、发软。
3. **主题色要整面地说。** 一个界面要有主色调和鲜明的对比。主色给一个大面：色面、色带或大主键。撒成十几个小点只会显得花，不会显得有主题。
4. **主次靠反差。** 字号、明度、饱和度、面积四个杠杆，至少拉开一个。每屏只有一个最大的元素。跳跃率高显得有活力，低显得端庄，但不能"中间一团"。
5. **结构本身就是信息。** 线、框、编号、标签、色块，每一个都要承载信息。没有信息的结构就是装饰；装饰越多，越像模板。
6. **落地。** 每个元素要么贴边，要么出血，要么压在别的东西上，要么和别的元素共用一条轴线。悬在空中的卡片就是"飘"。
7. **模块之间要有关系。** 用邻近、对齐、颜色延续和有意义的遮挡，让模块成组、成链、成层次。总览和细节之间要看得出连接。
8. **克制。** 大胆只花在一个地方：一个主题面、一个主角、一个主动作。出门前照镜子，再摘掉一件饰品。
9. **物要画到位。** 简单而精确的几何、统一的光源、正确的视觉修正，胜过现成的复杂素材。低质素材一出现，整体就显得廉价。
10. **母题来自题材本身的世界。** 主母题不超过两个，再配几个具体的实物子母题。从产品所在的世界里找，不从"通用 UI 套件"里拿。
11. **文字也是设计。** 文字只为让人看懂、会用而存在。产品姿态要放低：给事实，不说教；不说明显而易见的东西；同一个视口里不重复。
12. **用证据代替感觉。** 渲染真实尺寸，做模糊测试，算占比和对比度，和原作并排看。"我觉得还行"不是交付标准。

## 二、诊断词典：用户的形容词 → 原因 → 改法

| 用户说 | 常见原因 | 改法 |
|---|---|---|
| **飘 / 浮** | 卡片悬空；元素之间没有遮挡、对齐或共用边；阴影又大又糊；四周留白均匀 | 让元素落地：贴边、出血、压叠、共用轴线；阴影改硬、改短，带上色相 |
| **软** | 缺深色块；大面积淡彩（pale 或 light 色调）；插画罩白雾；字号挤在中间档；处处圆角 | 加一块重的形，主色整面出现，插画用满色；拉开跳跃率；结构用直线和小圆角 |
| **AI 味 / 模板味** | 等大等圆角的卡片网格；"图标 + 短词"一行却没有内容；渐变光斑；全大写小标签；所有元素一样重 | 从题材里找母题；用一个大胆的结构取代卡片堆；删掉没有信息的装饰 |
| **臃肿 / 啰嗦** | 说明文字、引导、建议；功能重复的按钮；同一信息出现两次；连默认状态都标出来 | 按"事实 → 动作"重新排；合并控件；默认状态不显示 |
| **廉价 / 低质** | 现成剪贴画（拨片、星星、夹子、贴纸）；胖圆角；光源方向不统一；白边字滥用；锯齿 | 自己画几何精确的形；统一光源；描边字只留给一两类关键词 |
| **随意 / 乱放** | 没有网格，位置说不出理由，间距不成体系 | 定网格和轴线；每个元素都要和至少一个其他元素对齐；间距按倍数走 |
| **闷 / 沉** | 深色太多，没有亮点，没有主题色 | 加一个高明度、高饱和的焦点，深色只做承托 |
| **花 / 乱** | 主色太多；纹理和图案处处都有；每个模块各说各的 | 主色只留一个；纹理降到 3–12% 透明度；统一语汇 |
| **散** | 模块之间没有关系，像几张卡片拼在一起 | 共用轴线、颜色延续、遮挡、连接线或楔形 |
| **挤** | 留白被装饰填满；行距太小；信息没有分组 | 分组以后组间距要明显大于组内距；删掉装饰 |
| **平** | 没有层次：没有前后关系，明度相近，没有大小反差 | 前中后三层；明暗拉开；一个元素做大 |
| **幼稚** | 糖果色全饱和堆在一起；圆角过大；字体卡通；装饰过量 | 加一块成熟的中性色（墨、灰、纸）承托；收紧圆角；只留一个可爱点 |
| **冷 / 工具感** | 只有灰和白；没有品牌色；排版像 PDF 阅读器 | 加一个主题面或色带；用满色插画；给标题做字形处理 |
| **不精致** | 细节没做到：内外圆角不嵌套；图标线宽不一；没有视觉修正；对齐差 1–2px | 用 2 倍图检查；按 `references/detail-craft.md` 逐项过 |

## 三、流程

1. **定事实。** 这一屏要回答哪几个问题？按重要程度排序。不在清单上的东西不上屏。
2. **看原作，不凭记忆。** 打开参考作品的真实截图，记录可观察的锚点：位置、大小、遮挡、颜色占比。方法见 `references/research.md`。
3. **画三值缩略。** 先确定主题面、重块、承托面（纸或白板）、焦点、主动作分别在哪里。三值图不成立，就不进细节。
4. **定少量变量。**
   - 一个主色加一个深色加一个承托色；
   - 一套字号阶梯（4–5 档）；
   - 一个品牌角或一种形状语言；
   - 圆角分档。
5. **用真实素材做小样。** 用真实的字体、图片和数据，按真实尺寸渲染。小样放在临时目录，不进产品代码。
6. **自检：**
   - `python tools/notan.py <outdir> <png...>`：看明暗结构和色调占比；
   - `python tools/contrast.py <fg> <bg>`：正文 ≥ 4.5，大字 ≥ 3；
   - 2 倍图看细节；
   - 和参考原作并排看；
   - 过清单。
7. **自我批评。** 每轮至少删掉一样东西。哪个框能删？哪句话能删？哪个元素说不出位置理由？
8. **给用户看。**
   - 一轮只问 2–4 个决定，让用户判断方案是活是死，不要把几个方案混在一起；
   - 被否掉的东西记进项目的反面清单，下一轮不再出现。

## 四、交付前清单

- [ ] 模糊三阶后有大形，焦点明确
- [ ] 主题色有一个"面"，不是碎点
- [ ] 每屏只有一个最大元素，跳跃率明确，没有中间一团的字号
- [ ] 每个元素都落地，至少和一个其他元素对齐；有遮挡的话，遮挡表达的是从属关系
- [ ] 模块之间看得出关系：成组、成链、成层次
- [ ] 所有框都有存在的理由；能用线、色面、留白分开的，就不用框
- [ ] 只有一个光源；圆角分档，内外嵌套；图标线宽统一；做了视觉修正
- [ ] 没有现成剪贴画，没有滥用描边字
- [ ] 没有说明、引导、建议，没有默认状态文字，没有重复信息和重复控件
- [ ] 纯黑、纯白、灰阴影都换成了带色相的版本
- [ ] 正文对比度 ≥ 4.5；色盲用户也能分辨，状态不只靠颜色区分
- [ ] 换皮肤或换主题时，几何不变，只换颜料
