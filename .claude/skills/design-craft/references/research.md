# 调研方法

## 1. 看原图，不凭记忆

- **用浏览器看参考作品的真实截图**，比如官方截图、实况视频的缩略图、玩家截图。凭记忆描述的参考一定会失真。
- **Google 图片会弹人机验证，不要去绕过，** 换 Bing 图片。在结果页可以用脚本取出原图地址，例如 `a.iusc` 元素的 `m` 属性 JSON 里的 `murl` 字段，再直接打开原图查看。
- **只看，不下载，** 除非用户同意下载。含官方美术的参考和小样，不发布到公开页面。

## 2. 记录可观察的锚点

- **每个样本记这些：**
  - 元素和它的位置、大小；
  - 遮挡关系；
  - 颜色占比；
  - 字的处理；
  - 承载的信息；
  - 结构性手势。
- **一个特征至少在 3/4 的样本里出现，才算规律。**
- **形容词不算结论。** "很精致"要拆成看得见的做法，比如"白边 2px""前导零做淡""阴影偏移 4px 不模糊"。

## 3. 量化

- **`tools/notan.py`：** 先模糊，再统计暗、中、亮三阶占比，以及鲜艳色和淡彩的占比，同时输出三阶缩略图。拿用户认可的画面和自己的画面并排对比，差距会变成具体的数字。
- **`tools/contrast.py`：** 计算 WCAG 对比度。
- **测量原作：** 角度可以拟合 Logo 边缘的斜率来得到；颜色在截图上取样；尺寸按比例换算。

## 4. 反面参考与发散

- **反面参考：** 列出"不是什么"，包括用户否掉的、行业里泛滥的、AI 默认会生成的。
- **发散、淘汰、变异：**
  - 每轮做 2–3 个空间逻辑不同的方案，不是同一布局换配色；
  - 用户只判活死，不把几个方案混在一起；
  - 活下来的方案再做有名字的变体。
- **模糊测试：** 所有方案模糊后并排，看哪个有大形、哪个能被认出。

## 5. 和用户沟通

- **一轮只问 2–4 个决定。** 用小样说话，不用长篇解释。
- **用户的形容词**（飘、软、AI 味……）用 SKILL.md 里的诊断词典翻译成原因和改法，再回给用户确认。
- **被否掉的东西写进项目的反面清单，** 下一轮不再出现。用户的原话要记下来。
- **用户说"先别动手"，** 就只调研、做小样、写文档，不改产品代码。

## 6. 可读资料

- **色彩：**
  - Josef Albers《Interaction of Color》，讲色彩相对性；
  - Johannes Itten 的七种对比；
  - PCCS 色调体系；
  - notan 明暗结构。
- **版面与字：**
  - Josef Müller-Brockmann《Grid Systems》；
  - Robert Bringhurst《The Elements of Typographic Style》；
  - 日本设计里的"跳跃率"和"版面率"；
  - 和欧混植。
- **信息：**
  - Edward Tufte，讲数据墨水比和小倍数；
  - Ben Shneiderman，讲"先总览、再缩放过滤、按需看细节"。
- **游戏 UI：**
  - 《UI のモチーフテクニック》，讲主母题不超过两个，再配实物子母题；
  - CEDEC 2022 上 CyberConnect2 的分享，讲角色游戏 UI 的世界观与字体选择流程；
  - Persona 5 的 UI 分析。
- **细节：**
  - "プロ感"技巧集；
  - 嵌套圆角公式；
  - 袋文字做法。
