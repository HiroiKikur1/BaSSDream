# 人手做的界面：BaSSDream 设计准则

## 0. 先弄清楚“飘”是什么

用户说的“飘”不是元素在物理上悬浮，而是**看起来不像人做的，没有真实的落地感**。
AI 做界面的方式是：从代码原语（矩形、圆角矩形、纯色、渐变、文字、模糊投影）出发，套用网页上最常见的参数，拼出“看起来还行”的东西。结果每个元素都没有来历——它不代表现实里的任何东西，也不是为这个软件的某个具体问题做出的决定。

成熟软件（Mac OS X Aqua、Windows XP/7、Guitar Pro、日式手游 UI）的做法是反过来的：

1. **先有一个具体的隐喻或原型**（唱片库、乐谱、舞台、街机面板），每个元素都能说出“它在现实里是什么”。
2. **画面由“做出来的素材”构成**，有材质、有统一光源、有落在某个表面上的阴影；不是参数拼出来的。
3. **界面是稳定的**：固定的框架、固定的位置、可预测的行为，只有用户让它动它才动。
4. **每处尺寸和形状都有具体理由**，因内容而异，而不是全局统一成一个“好看的数”。

下面每一条都是这四点的展开。**不要**把“去掉圆角、改成 1px 线、等宽数字”当成答案——那只是另一种流行的扁平风格，同样是 AI 味。

## 1. 从隐喻出发，不从组件库出发

- 动手前写一句话：这个界面**在现实里是什么**。BaSSDream 的现有答案：
  - 选曲主界面 = 游戏（GBP）的选曲画面：舞台背景、乐队色、斜切的街机面板。
  - 谱面页 = 印刷的贝斯谱册（页眉、排练号方框、TAB 在五线谱下方，GP 的版式）。
  - 评测结算 = 游戏的结算页（判定色、评级、分数）。
  - 练琴日历 = 纸质打卡日历。
- 每加一个元素，问：它在这个隐喻里对应什么？答不出来就不加。
- Apple HIG 的要求：界面要**反映用户的心智模型**（Reflect the User's Mental Model）。iTunes 的播放键像收音机和 CD 机上的按键，搜索框和 Finder 的一模一样——熟悉感来自现实和系统惯例，不来自“现代感”。
- 用这个领域自己的记号和单位：♩ = 158、4/4、3♯、小节号、TAB 六线、判定 PERFECT/GREAT/GOOD/BAD/MISS。不要用通用的“卡片 + 标签 + 数字”去表达乐谱信息。

## 2. 先找参照，再画

- 做任何一个画面前，先找 2–3 张**真实成熟产品**的同类画面作参照（GBP 对应界面、Guitar Pro 8、Rocksmith、foobar2000、老版 iTunes），写下“这个元素借自哪里、为什么”。
- 参照要具体到截图，不要凭“印象中的某种风格”。
- 用户明确要求：乐队标识只用官方素材，不要自己画乐队文字或 logo。
- 找不到参照时，问用户要截图，不要自己发明一种风格。

## 3. 用素材的逻辑画，而不是用 CSS 的逻辑画

手游和 Aqua 的界面元素是设计师在 Photoshop/Illustrator 里做的**素材**。在 WPF 里用代码画时，要按素材的逻辑去画：

### 3.1 统一光源
- 全软件**一个光源**，从正上方略偏前（Aqua 的做法；Mac OS 9 之前是左上）。选定后所有元素服从它。
- 于是：上沿有细高光（1px 亮线或向下衰减的亮带），下沿偏暗，影子在正下方。
- **禁止**：不同元素的影子方向不同、同一界面既有“凸起”又有“凹陷”却没有理由、影子朝四周均匀发散（`ShadowDepth="0"` 的大模糊光晕）。

### 3.2 影子要让东西“落在一个表面上”
- HIG：影子“应让图标像是放在一个表面上”。影子是**接触影**：贴近物体、偏下、边缘相对清楚（手游常用：黑色、正片叠底、不透明度约 30%、y 偏移 2、模糊 4）。
- 大半径、零偏移、低不透明度的柔光（常见于网页卡片）会让物体脱离地面，这正是“飘”的来源之一。
- 有厚度的东西（按钮、面板、贴纸）优先用**实体厚度**表达：下沿一条更深的同色边，按下时厚度消失、面板下沉。

### 3.3 材质
- 每种表面确定它是什么材料：纸（谱面、日历）、塑料/亚克力（按钮、面板）、金属（奖杯、评级徽章）、玻璃（少用）。HIG：让图标“看起来像真的材料做的，传达重量和手感”。
- 材料决定高光：塑料是柔和宽高光，金属是锐利的明暗交替，纸几乎没有高光但有纤维颗粒。
- 透明只在现实里也会透明时使用（HIG：“你不会见到透明的球鞋”）。

### 3.4 描边
- 游戏 UI 的元素和文字压在复杂背景（舞台照片、曲绘）上时，用**白色或深色描边**把它从背景里分离出来（GBP 的 logo 本身就带白描边）。描边粗细按元素大小定，不全局统一。
- 大标题文字：填色 + 描边 + 接触影，三层都要有。

### 3.5 形状
- 形状来自隐喻：街机面板是斜切的（logo 斜体约 15°）、印刷谱的方框是直角、贴纸有圆角和厚度。
- 不同对象用不同的形状语言，但同一类对象永远同一种。**不要**全软件统一一个圆角值。

### 3.6 优先用真素材
- 能用位图素材的地方用位图（官方乐队素材、舞台照、曲绘、手工调过的图标），代码只负责拼装和状态。
- 图标按显示尺寸单独调（HIG 要求 16/32/128 各出一版“hint”）；不要用 Unicode 符号或 emoji 充当图标。
- 素材放 `src-native/assets/`，作为程序资源嵌入，不引用 `E:\` 绝对路径。

## 4. 稳定感（Perceived Stability）

HIG：“界面要提供可理解、熟悉、可预测的环境……给用户视觉上的稳定感。”

- **框架不动**：标题栏、顶栏、侧栏、底部状态区的位置和尺寸永远固定。切换曲目、筛选、打开浮层时，框架不重新排版、不跳动。
- **背景不自己动**：装饰性的循环动画（漂移的字、呼吸光、粒子）会让眼睛一直找不到“地面”。背景可以随内容换（换曲目时换舞台照），但换完就静止。
- **不适用的操作变灰，不要消失**：按钮的位置本身就是信息。
- **记住用户的设置**：窗口位置、上次选的曲目和分类、排序、音量、谱面缩放，重启后原样恢复。
- **状态要看得见**：后台任务（伴奏补齐、扒谱）有明确的进度和数量（HIG 的例子：“正在复制第 30 / 850 个文件”），不要只放一个转圈。

## 5. 反馈与动效

- 每个操作**立即**有反馈（按下的那一帧就变），不要等动画开始。
- HIG：动画“少量使用时”最好的用途是**说明关系和去向**——窗口最小化时滑进 Dock，告诉用户去哪找。动效要回答“东西从哪来、到哪去”。
- 不要给每个元素加淡入、缩放、弹跳。界面交互保持短、直接；弹簧、过冲、碎裂这类表演性动效只留给少数“仪式时刻”（开机动画、结算页出分）。
- 表演性动效要有物理依据：有质量（加速和减速）、有接触（撞击时压缩、回弹）、有来源（从哪个物体飞出）。

## 6. 信息的排布

- **按使用频率分主次**：最常用的操作最大、固定在最好按的位置（开始练习）；少用的放菜单或右键（HIG：功能不要只藏在右键菜单里，但也不必全摆在主界面）。
- 用户是专业乐手：信息密度可以高，但要对齐——同类数据放同一列、同一基线、同一单位。
- 尺寸因内容而异：长标题的行、带版本标记的行、选中的行，本来就应该不一样；不要为了“整齐”把所有东西塞进相同的卡片。
- 文案遵守 AGENTS.md：不说教、不加英文副标题、Toast 只写事实。

## 7. 一致性（三个层次）

HIG 的一致性检查：
1. **与平台一致**：Windows 的快捷键（Ctrl+Z、Ctrl+F、Esc 关闭、Enter 确认）、右键菜单、拖放、滚轮行为照 Windows 惯例。
2. **与自身一致**：同一个概念全软件同一个名字、同一个图标、同一个颜色。例：品牌粉只有 `#E50050` 一个值（从资源字典取）；判定色只用于判定。
3. **与旧版本一致**：用户已经熟悉的位置和叫法不要随便改。改版以“保持现状”为默认，只在有明确理由时动。

## 8. WPF 实现要点

- 颜色、字号、间距、形状从资源字典取名字（`Palette.xaml` / `Type.xaml` / `Metrics.xaml`），不在 XAML/C# 里写字面量色值。
- 高光和厚度用分层的 `Border` / `GeometryDrawing` 画，不用已淘汰的 `BevelBitmapEffect`；`DropShadowEffect` 只用于静止元素，不要挂在会动或会缩放的元素上（每帧重新光栅化）。需要大量阴影时预渲染成 PNG。
- 自绘控件（谱面、报告页）：画刷、画笔、`Geometry` 全部 `Freeze()` 并复用；反复出现的文字（品位数字 0–24、小节号）缓存成 `GlyphRun`；按行缓存 `DrawingVisual`，选择和播放光标单独一层，改动只重画变化的层。
- 位图用 `DecodePixelWidth` 按显示尺寸解码，在后台线程解码后 `Freeze()`。
- 全局 `UseLayoutRounding="True"`，1px 线不落在半像素上。
- 动效用 `CompositionTarget.Rendering` 按时间计算状态（可暂停、可跳过、掉帧不错位）；大量粒子画在 `WriteableBitmap` 上，不建成千上万个元素。

## 9. 交付前自查

逐条回答，有一条是“是”就回去改：

- [ ] 有没有哪个元素说不出它在隐喻里对应什么？
- [ ] 有没有照着“现代/简洁/高级”之类的词做，而不是照着一张具体的参照截图做？
- [ ] 光源是否不统一？有没有四周发散的柔光阴影？
- [ ] 有没有全局统一的圆角/间距/卡片，而内容本身并不相同？
- [ ] 背景或装饰有没有在用户没操作时自己动？
- [ ] 切换内容时框架有没有跳动、重排？
- [ ] 有没有用 Unicode/emoji 当图标，或自己画了乐队标识？
- [ ] 有没有字面量颜色、第二个“品牌粉”、只在一处出现的字号？
- [ ] 动效是否在说明“从哪来到哪去”，还是只是装饰？
- [ ] 文案有没有说教、英文副标题、冗长 Toast？
- [ ] 用户的设置（窗口、选中项、排序、音量）重启后是否还在？

## 资料

- Apple Human Interface Guidelines（2005-12-06 版）第 3 章 Human Interface Design Principles（Reflect the User's Mental Model、Feedback and Communication、Consistency、Forgiveness、Perceived Stability、Aesthetic Integrity）；第 10 章 Icon Perspectives and Materials（统一光源、材质、影子让物体落在表面上、按尺寸出 hint）。
- Apple HIG 1987 原则：隐喻、直接操作、看见并指向、一致性、所见即所得、用户控制、反馈与对话、宽容、稳定感、审美完整性。
- Nielsen Norman Group 眼动实验：扁平界面“弱提示”版本比强提示版本多花约 22% 时间、多 25% 注视次数。
- 日式游戏 UI 制作经验：光源统一（光在左上则影在右下，光在上则影在正下）、描边分离背景、接触影参数（黑、正片叠底、30%、y+2、模糊 4）、金属用利落的渐变。
- Windows User Experience Interaction Guidelines（Windows 7）：让设计匹配用途；可调整大小的窗口优先，避免截断数据。
